# 2.1 The pages are history entries (HOO-2719)

**Goal:** `/new`, `/tutorials` and `/programs` stay in the address while their
page shows, Back and Forward open and close the pages, and a reload stays on
the page.

**Approach:** take the pages half of HOO-2689's PR #441 (scope/tutorial-flow)
onto scope/interface-2, with `/new` added and without `/home`, so the two
branches meet on one model. Home keeps no path of its own here: a page closed
over Home goes back to the path Home showed on.

## Steps

1. `routes/catalog-paths.ts`: `pathOfCatalogPage(page)`, the inverse of
   `catalogPageOfPath` (`new-project` is `/new`); `isStartPath` moves here from
   `start-view.ts`. In-source tests: the round trip for all three.
2. `routes/open-page-from-link.ts`: open the page and mount the work (or Home)
   under it with `handleRoute()`; no replace with `/`. Unit test rewritten.
3. `widgets/catalog/model/catalog-page.ts`: `useCatalogPage` only reads the
   store; closing on another path moves to the new hook.
4. `views/flow/use-view-path.ts` (new, the shape of #441's without Home's
   path), used by `Flow`:
   - a path come to opens the page it names, or closes the page shown;
   - a page shown off its path pushes the page's path;
   - a page closed while the path is still its own goes back: to the path
     Home showed on when Home shows, else to the open project's path (a
     tutorial's route, or `/`);
   - a shared project (`PgExplorer.isTemporary`) never moves the path.
   Unit tests with the router and explorer stubbed.
5. `widgets/home/model/start-view.ts`: the work cannot be drawn on any start
   path with no project open (was `/` only), so a reload on a page's path with
   no project shows Home under it.
6. `widgets/app-nav/ui/ProjectList.tsx`: `onPicked` once the pick is open, as
   #441 does, so closing the page cannot send the path back to the project
   that was open before.
7. Spec delta (`specs/client-v2-layout/spec.md`): the routes stay in the
   address while their page shows; Back or Forward to another path closes it.
8. e2e: `e2e/page-history.e2e.spec.ts`, Back and reload for each of the three;
   update the `catalog` and `new-project` specs that expected `/`.

## Gate

`yarn run check`; the e2e specs this PR adds or changes, locally.
