# 2.6 ResizeObserver loop notice: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the global `error` listener stops logging the browser's ResizeObserver loop notice, and `docs/testing.md` lists every console message C-1/C-4 expect.

**Architecture:** a predicate in `shared/lib/logger/global-handlers.ts` recognises the notice by its exact message and the absence of an `error`; `onError` returns before `log.panic` when it matches. Everything else reaches `panic` as before.

**Tech Stack:** TypeScript, vitest + jsdom.

**Spec:** `openspec/changes/telemetry-and-logging/specs/client-v2-logging/spec.md`, requirement "Unhandled and render errors go through the logger"; ticket HOO-2125.

## Global Constraints

- The message is matched exactly: `ResizeObserver loop completed with undelivered notifications.` (with the full stop, as Playwright's Chromium reported it on `new-face`, 2026-10-19).
- An `ErrorEvent` that carries an `error` is always logged, whatever its message.
- `unhandledrejection` is unchanged.

## Review Focus

1. A real `Error` thrown with the same text: logged (the `error` is present). Test in Task 1.
2. Another ResizeObserver message (`ResizeObserver loop limit exceeded`, older Chrome): logged, the ticket filters one notice only. Test in Task 1.
3. A cross-origin `Script error.` with no `error`: still logged (existing test).
