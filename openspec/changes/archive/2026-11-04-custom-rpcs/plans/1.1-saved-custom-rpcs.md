# Saved custom RPCs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several named custom RPCs in Settings, Network: saved in this browser, picked as chips beside Devnet and Mainnet, added, edited and removed inline.

**Architecture:** A new entity `entities/custom-rpc` owns the list (pure rules + a `localStorage`-backed store with a change event). The `settings-page` widget draws the extra chips in `BaseNetworkChoice` and a new `BaseCustomRpcs` (list + form), and `SettingsPage` connects them to the store and `PgSettings.connection.endpoint`.

**Tech Stack:** React 19, TypeScript, design-system components in `@/shared/ui` (`segmented`, `field`, `input`, `input-group`, `button`), vitest (in-source blocks and `*.test.tsx`), Playwright.

**Spec:** `openspec/changes/custom-rpcs/specs/client-v2-custom-rpcs/spec.md`, `openspec/changes/custom-rpcs/design.md`

## Global Constraints

- Copy, verbatim: "Add custom RPC", "Name", "RPC URL", "Save", "Cancel", "Any Solana RPC URL. It stays in this browser.", "Enter a URL that starts with https://", "Already saved as {name}.", "Removed {name}.", "Removed {name}. Network is Devnet now.", "Undo".
- aria: chips group `Network`; list `Custom RPCs`; row buttons `Edit {name}`, `Remove {name}`.
- URL rule: `https:`; `http:` only for hostname `localhost` or `127.0.0.1`.
- Name: trimmed, at most 32 characters; empty saves as `new URL(url).host`.
- Storage key `customRpcs`, JSON `Array<{ name: string; url: string }>`.
- Never render a saved URL outside the edit field; never put URL, host or name in an event.
- Phone: targets 44 px tall (`max-md:h-12`, as the chips already are); chips wrap at 320 px.

## Review Focus

- `customRpcs` holding garbage (not JSON, not an array, entries without a string `url`) → reads as the valid entries only, no throw.
- Editing the picked RPC's URL → the connection moves to the new URL (not left on the old one, which would be re-adopted as a duplicate).
- Undo after the picked one was removed and Devnet set → the RPC comes back at its index and is picked again.
- A URL differing only by a trailing slash or host case (`https://RPC.example.com/`) → compared after `new URL(...).href`, so it is a duplicate.
- Two tabs: the list is re-read on the `storage` event, so a chip added in one tab shows in the other after it re-renders.

### Task 1: The `custom-rpc` entity

**Files:**
- Create: `client-v2/src/entities/custom-rpc/model/custom-rpcs.ts` (rules, store, in-source tests)
- Create: `client-v2/src/entities/custom-rpc/index.ts`

**Interfaces:**
- Produces:
  - `type CustomRpc = { name: string; url: string }`
  - `checkRpcUrl(value: string): { ok: true; url: string } | { ok: false; reason: "format" }` (`url` is `new URL(value).href`)
  - `hostOf(url: string): string`
  - `PgCustomRpcs.list(): CustomRpc[]`
  - `PgCustomRpcs.save(input: CustomRpc): SaveResult` and `PgCustomRpcs.replace(url: string, input: CustomRpc): SaveResult` (in place), `SaveResult = { ok: true; rpc } | { ok: false; reason: "format" } | { ok: false; reason: "duplicate"; name } | { ok: false; reason: "storage" }`
  - `PgCustomRpcs.remove(url: string): { rpc: CustomRpc; index: number } | undefined`
  - `PgCustomRpcs.restore(rpc: CustomRpc, index: number): boolean` (false when the write was refused)
  - `PgCustomRpcs.adopt(endpoint: string): string | undefined` — lists `{ name: hostOf, url }` when `endpoint` passes `checkRpcUrl` and is no address the app knows by name; answers the listed (normalised) URL.
  - `PgCustomRpcs.onDidChange(cb: () => void): { dispose(): void }` — fires on its own writes and on the window `storage` event for `customRpcs`.
