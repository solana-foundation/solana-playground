# Tighten the client-v2 test setup: implementation plan

> **As built:** where this plan and `../design.md` differ, the design records what shipped (the `paths` mapping for mocha, `checkedAs`, the error codes). The steps below are the plan as written before the build.

> **For agentic workers:** executed inline (superpowers:executing-plans), one commit per task.

**Goal:** HOO-1914's DOD: `it.each` type-checks, test globals fail the type check outside tests, the `PgFs` mock is compiler-checked, no test gets a real `BroadcastChannel` unasked, test names unchanged plus the added ones.

**Architecture:** see `../design.md`. Two TypeScript programs (`tsconfig.json` with test globals, `tsconfig.app.json` without and without test files); `tsconfig.json` `paths` sends `"mocha"` to a local declaration, `@types/mocha` kept for the editor; test-only edits elsewhere.

**Tech stack:** TypeScript 5.0.4 (pinned), vitest, yarn 1, Node 22.

**Spec:** `../specs/client-v2-unit-tests/spec.md`, `../proposal.md`, HOO-1914.

## Global constraints

- All commands from `client-v2/`, Node 22 on `PATH`.
- Baseline: `npx vitest run --reporter=json` on `foundation/master` @ 76643a2cb, 2984 tests, all passed. The final run is compared name for name.
- No change to runtime behaviour of `js-runtime.ts` (user test programs still get the same mocha globals).
- Commits: Conventional Commits, `(client-v2)` scope, no attribution trailers.

## Review focus

- A test file whose name the `tsconfig.app.json` exclude misses (e.g. `__tests__/` helpers, `*.test.mts`, `test-utils/`) fails the app check on its globals → the exclude list is checked by running the app program on the whole tree.
- `js-runtime.ts` first run: `describe` read before `mocha.setup` must still skip the reset (was a caught `ReferenceError`, becomes `undefined`).
- A module that both tests and production import from `src/test-utils/` → excluded from the app program only if nothing in production imports it (checked by grep).
- A test that relied on Node's `BroadcastChannel` silently → the name-for-name comparison catches a vanished or failing test.
- `satisfies` on the mock must not change the inferred type tests rely on (`__files`).
