# Writes against their own reference: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans
> (inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a write block may carry `ref` and `start`; the check and the
engine place it against them, so Lumberjack's and Zero Copy's step 1 build
`lib.rs` exactly as the prototype does.

**Architecture:** schema and types (`entities/tutorial`), the check
(`checkDefinition`), then the engine: `groundOf` in `landing.ts` picks the
reference and start for a write, the reducer copies `ref`/`start` into the
write effect, `store.ts` passes `groundOf`'s pair to `insertBlock`.
`AUTHORING.md` last.

**Spec:** `openspec/changes/tutorial-write-anchors/` (proposal, design, the
`tutorial-definition` delta).

**Success metric (from the ticket):** on the preview, Lumberjack's and Zero
Copy's step 1 writes land in the right place in `lib.rs`, with no stray `}`
or `bump,` moved. Until those tutorials land (HOO-2362, HOO-2363), the
measure is the unit replay: `lib.rs` after step 1's writes equals the
prototype's broken build, byte for byte, and after the fix equals the target.

## Fixture

`src/tutorials/__tests__/write-anchors/prototype-step1.json`: step 1 of
Lumberjack and Zero Copy (start, target, every write with its `ref` and
`start`), dumped from `origin/almaz/mobile-tutorial-prototype` by running the
lesson modules. Replaying them with the prototype's `insertBlock` gives the
broken build equal to the last write's `ref` and the final file equal to the
target; against the step's target alone, a write of each lesson's broken
build lands elsewhere, and Zero Copy's fix never reaches its target.

## Steps

- [x] 1. `groundOf` in `landing.ts` with in-source tests: own `ref`/`start`

      `….writes.block`, a block twice in its `ref` at `….writes.ref`. Test

- [x] 4. Reducer: the write effect carries `ref`/`start` when the block has
      them (reducer in-source test); `store.ts` lands through `groundOf`

- [x] 5. `AUTHORING.md`: both fields, when to use them, the check's rule.
- [ ] 6. `yarn run check`; sx review full + default; PR into
      `scope/tutorial-flow`.

## Review focus

1. A write without `ref`/`start` lands exactly as before (existing store and
   walk tests unchanged).
2. `start: ""` is a real value (an empty file), not "absent".
3. The check's "exactly once" counts the block's lines in a row in the `ref`
   the way the check's own `holds` reads them (trimmed, blank lines dropped,
   overlapping runs counted). The engine reads comments and quotes away too,
   so `write-anchors.test.ts` also replays every tutorial's writes through the
   engine and fails on any that would be appended.
