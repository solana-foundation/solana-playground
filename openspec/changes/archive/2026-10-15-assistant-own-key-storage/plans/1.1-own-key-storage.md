# Own key in sessionStorage: implementation plan

> **Superseded.** This plan was the starting point for tasks 1.1 to 3.1. The
> code and `design.md` supersede it, and its steps are not ticked one by one.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A key-based assistant connection survives a reload of its tab via `sessionStorage`, dies with the tab, is forgotten on disconnect, and never lands anywhere durable.

**Architecture:** `model/remembered-backend.ts` stays the one module that decides what comes back on reload. It gains a `sessionStorage` entry, `assistant.connection`, holding the whole `Connection` for a key-based backend; the `localStorage` id for the default backend is unchanged. `PgAssistant.connect` and `disconnect` call it; `Connect.tsx` reconnects from it on mount.

**Tech Stack:** TypeScript, React 19, vitest (jsdom), Playwright.

**Spec:** `openspec/changes/assistant-own-key-storage/specs/assistant-own-key/spec.md`, with `design.md` beside it. Covers tasks 1.1, 1.2, 2.1 and 3.1 of `tasks.md`; one PR.

## Global Constraints

- Storage: `sessionStorage` only for the key (Slava, 2026-10-13). Never `localStorage`, IndexedDB, a thread, the server, a log, telemetry or an error report.
- Every storage access is guarded; a `catch` is never empty, it logs through `createLogger("assistant:remembered-backend")` without the value and without `report: true`.
- No nested ternaries; ids from `src/shared/lib/ids` (none needed here).
- Tests build fixtures explicitly, no spread to make a new shape (`client-v2/AGENTS.md`).
- `#assistant-api-key` keeps its id.
- Commits: Conventional Commits, `feat(client-v2): ...`; no AI attribution.
- All commands run from `client-v2/` under Node 22.20 (`export PATH=~/.nvm/versions/node/v22.20.0/bin:$PATH`).

## Review Focus

1. A stored value written by an older or newer build (unknown provider id, missing key, bad effort): dropped, picker shown, no crash. Pinned in Task 1.
2. `sessionStorage` throwing on write but the page still working: connect succeeds in memory. Pinned in Task 1 (unit) and Task 3 (e2e).
3. The default-backend auto-reconnect racing the key-based one on load: the key-based one wins and the default effect skips because something is connected. Pinned in Task 3 (reload test asserts `connection.id`).
4. Switching from a key-based backend to the default leaves the old key in `sessionStorage`. Pinned in Task 1 and Task 3.
5. A failed write logging the connection object (and so the key): pinned in Task 1 by asserting no log entry contains the key.

```ts
import { createLogger } from "@/shared/lib/logger";
import type { Connection } from "../store";
import { PROVIDERS, type ProviderId } from "./types";

/**
 * Which backend to reconnect to on the next load.
 *
 * Two answers in two stores. The keyless default backend is remembered by id
 * in `localStorage`, across tabs and restarts: nothing secret is written.
 * A backend that needs the user's own key is remembered whole, key included,
 * in `sessionStorage`, which lives as long as this tab and no longer. Project
 * code runs in this origin and can read either store; `sessionStorage` bounds
 * that to the tab the user is already working in. See the design of the
 * OpenSpec change `assistant-own-key-storage` (HOO-1748).
 *
 * Every access is guarded. Storage throws rather than returning `null` in a
 * private window or with site data blocked, and the panel has to open either
 * way. A failure is logged by what was attempted, never with the value.
 */
const BACKEND_KEY = "assistant.backend";
const CONNECTION_KEY = "assistant.connection";

const DEFAULT_ID: ProviderId = "default";

const log = createLogger("assistant:remembered-backend");

const attempt = (what: string, run: () => void) => {
  try {
    run();
  } catch (error) {
    // Expected in a private window, so not reported; the panel asks again
    log.warn(`could not ${what}`, {
      context: { reason: error instanceof Error ? error.name : "unknown" },
    });
  }
};

const isRecord = (value: unknown): value is Record<string, unknown> =>
  typeof value === "object" && value !== null;

/** A stored connection, rebuilt field by field so nothing unknown rides along */
const parseConnection = (raw: string): Connection | null => {
  let value: unknown;
  try {
    value = JSON.parse(raw);
  } catch {
    // Malformed is handled by the caller, which drops the entry and logs it
    return null;
  }
  if (!isRecord(value) || typeof value.apiKey !== "string") return null;

  const provider = PROVIDERS.find((p) => p.id === value.id);
  if (!provider || provider.id === DEFAULT_ID) return null;

  const connection: Connection = { id: provider.id, apiKey: value.apiKey };

  if (value.endpoint !== undefined) {
    const { endpoint } = value;
    if (
      !isRecord(endpoint) ||
      typeof endpoint.baseUrl !== "string" ||
      typeof endpoint.model !== "string"
    ) {
      return null;
    }
    connection.endpoint = { baseUrl: endpoint.baseUrl, model: endpoint.model };
  }

  if (value.settings !== undefined) {
    const { settings } = value;
    const effort = provider.modelSettings?.efforts.find(
      (e) => isRecord(settings) && e === settings.effort
    );
    if (!isRecord(settings) || typeof settings.model !== "string" || !effort) {
      return null;
    }
    connection.settings = { model: settings.model, effort };
  }

  return connection;
};

/** Record the user's choice, so the next load of this tab can act on it */
export const rememberBackend = (connection: Connection) => {
  // Written down as a whole id rather than a flag, so switching to a
  // key-based backend overwrites it instead of leaving a stale `true` behind
  attempt("remember the backend", () =>
    localStorage.setItem(BACKEND_KEY, connection.id)
  );

  if (connection.id === DEFAULT_ID) {
    attempt("forget the previous key", () =>
      sessionStorage.removeItem(CONNECTION_KEY)
    );
    return;
  }

  const stored: Connection = { id: connection.id, apiKey: connection.apiKey };
  if (connection.endpoint) stored.endpoint = connection.endpoint;
  if (connection.settings) stored.settings = connection.settings;
  attempt("keep the connection for this tab", () =>
    sessionStorage.setItem(CONNECTION_KEY, JSON.stringify(stored))
  );
};

/** Drop both. Disconnecting is the user saying not to reconnect. */
export const forgetBackend = () => {
  attempt("forget the backend", () => localStorage.removeItem(BACKEND_KEY));
  attempt("forget the key", () => sessionStorage.removeItem(CONNECTION_KEY));
};

/** Whether this browser should reconnect to the default backend by itself */
export const isDefaultBackendRemembered = () => {
  try {
    return localStorage.getItem(BACKEND_KEY) === DEFAULT_ID;
  } catch (error) {
    log.warn("could not read the remembered backend", {
      context: { reason: error instanceof Error ? error.name : "unknown" },
    });
    return false;
  }
};

/** The key-based connection this tab was using before a reload, if any */
export const rememberedConnection = (): Connection | null => {
  let raw: string | null = null;
  attempt("read the connection kept for this tab", () => {
    raw = sessionStorage.getItem(CONNECTION_KEY);
  });
  if (raw === null) return null;

  const connection = parseConnection(raw);
  if (!connection) {
    log.warn("dropped a kept connection this build cannot use");
    attempt("drop the unusable connection", () =>
      sessionStorage.removeItem(CONNECTION_KEY)
    );
  }
  return connection;
};
```

`ProviderInfo.modelSettings.efforts` (`model/types.ts`) is the list of efforts a provider offers. Extract the two identical `reason` expressions into one `reasonOf(error)` helper if lint or review asks.

```
  server, and is never logged or synced. Project code runs in the same origin
  and could read it while the tab is open; that is why it is not in
  `localStorage`.
```
