# 1.1 Offline and slow-run lines: plan

Success metric (from [HOO-2581](https://linear.app/solana-fndn/issue/HOO-2581)):
offline, the nine network commands end at once with "You're offline. This
command needs a connection." (red) and the local ones run; a run quiet for
10 s prints "This is taking longer than usual." (blue) once. Tests cover both;
the PR carries before and after screenshots.

Design gaps (decided, sent to Design alignment, accepted 4 Nov 15:04):
prettier and rustfmt run offline; offline line `error`, slow line `info`;
the strip's elapsed time stays out.

Steps, each test first (`superpowers:test-driven-development`):

1. `utils/terminal/slow-run.ts` with an in-source block (fake timers): fires
   once after 10 s; `noteOutput` restarts; `noteQuestion` pauses and
   `noteAnswer` restarts the full 10 s; the stop function cancels; output from the
   line itself does not re-arm.
2. `TerminalLineError` takes `{ tone }`; `PgTerm.process` prints the line
   coloured by tone (`PgTerminal.error` / `PgTerminal.info`); in-source test
   of the colouring helper in `line-error.ts`.
3. `PgTerm.print` calls `noteOutput`; `PgShell.waitForInput` calls
   `noteQuestion`, and `noteAnswer` on the answer.
4. `command.ts`: `needsConnection?: true` on `CommandParam`; offline check
   before pre-checks; `watchSlowRun` around the outermost run only. Tests in
   `command.test.ts`: offline throws the line before pre-checks; online runs;
   a local command runs offline; nested run arms one clock.
5. Flag the nine commands; a test that lists every command's flag so a new
   one is a conscious choice.
6. e2e in `e2e/client-v2-terminal.e2e.spec.ts` (or the existing terminal
   spec): `context.setOffline(true)`, `build` → line; `help` → list.
7. Gate: `yarn run check`, the touched e2e spec, screenshots before/after.
