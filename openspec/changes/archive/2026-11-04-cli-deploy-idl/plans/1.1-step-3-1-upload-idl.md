# Plan 1.1: Step 3.1 Upload the IDL and Download IDL

Ticket: HOO-2487. Base: `scope/users-work`. Mode: inline, TDD.

**Success metric (from the ticket):** on the preview, a user copies the step
3.1 script, runs it against a Devnet program, and Explorer shows named
instructions; the IDL downloads from the dialog.

## Steps

1. `model/commands.ts`: `idlCommands({tool, cluster, name, programId})`
   returns the Program Metadata command, plus `anchor idl init` for Anchor.
   In-source tests first: both clusters' `--rpc` URLs, the Anchor line,
   `<program-id>` without an id.
2. `model/telemetry.ts`: `cli_command_copied` gains `step`;
   `cli_idl_downloaded` added.
3. `ui/DownloadIdl.tsx` (Base + connected): outline button "Download IDL",
   saves `<name>.json` (pretty JSON of `PgProgramInfo.idl`), off without an
   IDL. Test: saves the file name, disabled without IDL, event sent.
4. `ui/BaseCliDeployGuide.tsx`: `downloadIdl` slot beside `download` in step
   1; `hasIdl` prop; step "3.1 Upload the IDL" with a CodeBlock per command,
   `onCopy(step)`. `CliDeployGuide.test.tsx` first: commands shown per tool
   and cluster, no command without IDL, copy event carries `step`.
5. `ui/CliDeployGuide.tsx`: wire `hasIdl`, `DownloadIdl`, `step`.

## Gates

- `yarn run check` in `client-v2/` (types, unit, lint, format, spec).
- No e2e spec added or changed.
- Manual: the dialog in the dev server through Playwright, before/after
  screenshots; run the Program Metadata command's `--help` and, when a funded
  Devnet keypair is available, the command itself against a Devnet program.
