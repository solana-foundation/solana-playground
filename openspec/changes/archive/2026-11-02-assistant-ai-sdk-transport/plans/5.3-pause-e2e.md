# 5.3 The pause scenarios in the browser

Task 5.3 of [tasks.md](../tasks.md): the two scenarios under "A paused turn is
resumed, up to a limit" in
[specs/client-v2-ai/spec.md](../specs/client-v2-ai/spec.md) become Playwright
tests, through the default backend, with every endpoint answered by
`page.route`.

## Why this is possible in the browser

The default backend's model requests go to `/api/agent` on the page's own
origin (`DEFAULT_BACKEND_URL` in `src/shared/lib/ai/default-backend.ts`), in
the chat-completions shape, and `createOpenAICompatible` keeps the stream's
raw `finish_reason` as `rawFinishReason`, which `runTurn` in
`src/shared/lib/ai/run-turn.ts` compares with `pause_turn`. Verified by hand
on 2026-10-22 in Chrome against this branch at `1c535bf90`: with
`window.fetch` patched so the first POST answered a stream ending in
`finish_reason: "pause_turn"`, the panel showed the paused text, `runTurn`
logged `Resuming a paused turn` under `ai:run-turn`, the second POST's
`messages` ended with the paused assistant content, and the turn finished
with the real answer.

## The file

`client-v2/e2e/assistant-pause.e2e.spec.ts`, two tests, titled exactly:

- `client-v2-ai: A paused turn is resumed`
- `client-v2-ai: A turn that keeps pausing`

`scripts/spec-coverage.mjs` reads the first string argument of each `test(`
call, so the titles are literals.

### Shared setup

Follow `e2e/assistant-sign-in.e2e.spec.ts` (`connectDefault`, `send`):

1. `stubSession(page)` from `e2e/fixtures.ts`, so the panel offers the
   default backend.
2. `page.route("**/api/agent", ...)`: a GET answers
   `{ configured: true, model: "test-model" }`; a POST records
   `route.request().postDataJSON()` into an array and fulfils with
   `contentType: "text/event-stream"` and the next body from a queue.
3. `startProject(page, "<name>", LONG)` after `page.goto("/")`, then wait
   for the composer, `getByRole("textbox", { name: "Message the assistant"
   })`. Open More, then "Connect a model", and click the dialog's `Start`
   button, as `connectDefault` in `assistant-sign-in.e2e.spec.ts` does.
4. Send with `composer.fill("hello")` and a click on the `Send` button.

### Stream bodies

Re-declare a small helper in the spec; `src/shared/lib/ai/fake-provider.ts`
holds the same shapes but imports `vi`, so the Playwright process cannot load
it. Each frame is `data: <json>\n\n`:

```ts
{ choices: [{ index: 0, delta: { role: "assistant", content: text }, finish_reason: null }] }
{ choices: [{ index: 0, delta: {}, finish_reason: "pause_turn" }] }   // or "stop"
```

followed by `data: [DONE]\n\n`.

### Test 1: A paused turn is resumed

- Queue: a stream with text `first half ` ending in `pause_turn`, then a
  stream with text `second half` ending in `stop`.
- Assert both texts visible in the thread (`LONG` timeout). The panel may
  render them as two assistant items; assert each text, not their
  concatenation.
- Assert exactly two POSTs were recorded, and that the last entry of the
  second POST's `messages` has `role: "assistant"` and content containing
  `first half`. The hand run saw `content` as a plain string.
- Wrong implementation it catches: a `runTurn` that returns at `pause_turn`.
  One request, `second half` never appears.

### Test 2: A turn that keeps pausing

- Queue: every POST answers a stream ending in `pause_turn`, text
  `part <n> `.
- Assert the thread shows the error item whose text `AiTurnError` carries:
  `The turn paused <n> times without finishing.` (`Chat.tsx` passes the
  thrown message to `PgAssistant.addError`).
- Assert the number of POSTs is one more than the resume limit. Preferred:
  import `DEFAULT_MAX_RESUMES` from `../src/shared/lib/ai/run-turn` and
  assert `sent.length === DEFAULT_MAX_RESUMES + 1`, if the Playwright process
  loads that module (it imports the `ai` SDK) and
  `scripts/in-source-e2e-imports.test.mjs` stays green. Otherwise read `<n>`
  from the error text, assert `sent.length === n` and `n > 1`, and say so in
  the report.
- Wrong implementation it catches: a `runTurn` that resumes without a limit.
  The error never appears and the POST count keeps growing.
