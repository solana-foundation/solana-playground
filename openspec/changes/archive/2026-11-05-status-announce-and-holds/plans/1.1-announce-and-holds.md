# 1.1 Announce, hold, keep the build (HOO-2625)

**Success metric (from the ticket):** on a throttled connection the first build of the example finishes or is stopped knowingly, and no deploy can be started while the status says the network is down. Checked by the tests and once by hand after the landing.

**Design gaps, settled with design alignment 5 Nov:** the hold's reason goes on the pill's tooltip and beside Test, no new caption; the panel's "Reload comes back when the build ends."; the region says the network as "Devnet, not responding".

Each step is test first, seen failing, then the code.

1. `model/notice.ts`: `networkHold(network, online)`.
2. `model/announce.ts`: `announcement({ before, after, notice })`, `useAnnouncement`; `ui/StatusAnnouncer.tsx`, a test over the real region; mount once in `FlowFrame`.
3. `holdingReload(indicator, run)`: no Reload and the extra line while a run is under way; `useStatus` reads `PgFlow`.
4. `BaseDeploy` prop `networkHold`, pill disabled, reason on its tooltip; `Deploy` passes `useNetworkHold()`.
5. `Instruction`: `heldBecause` takes the hold first; Test disabled.
6. `commands/deploy`: `checkNetwork` first in `preChecks`.
7. `docs/assistant-context.md` if it says a deploy is always possible; `yarn sync-assistant-context` if it changes.
8. e2e in `client-v2-status.e2e.spec.ts`: offline holds the pill, region reads a failure.

**Gate:** `yarn run check` plus that spec; `fleet-testing.mjs`; screenshots before and after with Playwright.
