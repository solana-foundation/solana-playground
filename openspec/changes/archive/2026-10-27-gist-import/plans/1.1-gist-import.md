# Gist Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open a project from a gist URL, in the import dialog and from a link, signed out.

**Architecture:** `features/gist` (shared with HOO-1760) gains `lib/url.ts`
(URL -> gist ref) and `model/import.ts` (gist API -> files -> project or
temporary view, with telemetry). `ImportGithub` and a new `routes/gist`
call it. Layout comes from HOO-1760's `fromGistFiles`.

**Tech Stack:** TypeScript, vitest (in-source blocks and test files), Playwright.

**Spec:** `openspec/changes/gist-import/specs/gist-sharing/spec.md`, `design.md` beside it.

## Global Constraints

- Events: `gist_import_started`, `gist_import_succeeded`, `gist_import_failed`; prefix `gist` (registered by HOO-1760); params exactly as the spec's "Gist import is measured".
- Project name `gist-<owner>/<id>`, `gist-<owner>/<id>@<revision>` with a revision; owner from the API's `owner.login`, `anonymous` when the gist has none.
- Network through `fetch`, stubbed in tests with `vi.spyOn(globalThis, "fetch")`.
- No `crypto.randomUUID`, no empty `catch`, no nested ternaries (client-v2/CLAUDE.md).
- The dialog keeps its modal name `import-github` and its existing ids.

## Review Focus

- A URL with a trailing slash, `www.`, query string or `#file-x-rs` anchor must still parse (Task 1 table).
- An anonymous gist (no `owner`) must still import, as `gist-anonymous/<id>` (Task 2 test).
- A gist with zero usable files must fail as `no-program`, not create an empty project (Task 2 test).
- A network error (`fetch` rejects) must be `request-failed` with a message, not an unhandled rejection (Task 2 test).
- The `/gist/<id>/<revision>` link must pass the revision through (Task 3 route test via `parseGistRef`).

### Task 2: Import a gist

**Files:**
- Create: `client-v2/src/features/gist/model/import.ts`, `client-v2/src/features/gist/model/import.test.ts` (test file: it mocks `@/utils`)
- Modify: `client-v2/src/features/gist/model/telemetry.ts` (append events), `client-v2/src/features/gist/index.ts` (append exports), `client-v2/src/shared/lib/telemetry/prefixes.ts`

**Interfaces:**
- Consumes: Task 1's `GistRef`; HOO-1760's `fromGistFiles(files: Record<string, { content: string }>): { name: string | null; layout: "manifest" | "loose"; files: Record<string, string> }` and `GistFormatError` (with `reason: GistFormatReason`); `PgExplorer.getAllWorkspaceNames(): Promise<string[]>` (added in the review fixes: a link's temporary view holds no list in memory).
- Produces:
  - `type GistImportSource = "dialog" | "link"`
  - `type GistImportFailure = "not-found" | "rate-limited" | "too-large" | "invalid" | "no-program" | "request-failed"`
  - `class GistImportError extends Error { reason: GistImportFailure }`
  - `getGistFiles(ref: GistRef, from: GistImportSource): Promise<{ owner: string; files: TupleFiles }>` — reads, lays out, emits started/succeeded/failed.
  - `importGist(url: string, from: GistImportSource): Promise<void>` — `getGistFiles`, then `PgExplorer.createWorkspace(name, { files, skipNameValidation: true })`, or `switchWorkspace(name)` when `await PgExplorer.getAllWorkspaceNames()` has it (checked before any request when the URL names the owner).

- [ ] **Step 1: Write the failing tests** in `import.test.ts` (`vi.mock("@/utils")` for `PgExplorer`, `PgFramework.getFromFiles`; `fetch` via `vi.spyOn`; telemetry via `initTelemetry([memoryProvider()])` as `features/auth/model/telemetry.test.ts` does):
  - a manifest gist -> `createWorkspace("gist-alice/0123abcd", { files: [["src/lib.rs", ...], ["client/client.ts", ...]], skipNameValidation: true })`; events `gist_import_started {from:"dialog"}`, `gist_import_succeeded {from:"dialog", layout:"manifest"}`.
  - a loose gist (`lib.rs`, `anchor.test.ts`, `client.ts`, `notes.txt`) -> `src/lib.rs`, `tests/anchor.test.ts`, `client/client.ts`; `layout:"loose"`.
  - existing `gist-alice/0123abcd` -> `switchWorkspace`, `fetch` not called.
  - revision URL -> requests `https://api.github.com/gists/0123abcd/9f8e7d`, name `gist-alice/0123abcd@9f8e7d`.
  - anonymous gist (no `owner`) -> `gist-anonymous/0123abcd`.
  - truncated file -> fetches its `raw_url`, imports the whole text.
  - `truncated: true` on the gist -> `GistImportError` `too-large`.
  - 404 -> `not-found`, message names the gist and says the link may be out of date.
  - 403 with `x-ratelimit-remaining: 0` -> `rate-limited`, "try again later".
  - 500 -> `request-failed`, message carries `500`; `fetch` rejecting -> `request-failed`.
  - `GistFormatError` from the format -> `invalid`, message says the manifest is invalid.
  - `getFromFiles` resolving `undefined`, or no files -> `no-program`.
  - every failure sends `gist_import_failed {from, reason}` and no `createWorkspace`.
- [ ] **Step 2:** `yarn test-unit src/features/gist/model/import.test.ts` -> FAIL.
- [ ] **Step 3:** Implement. Error messages follow `PgGithub._getErrorMessage`'s wording with "gist" for "repository". Log failures with `createLogger("gist:import")`.
