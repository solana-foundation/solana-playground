# Mainnet deploy warning: implementation plan

> Inline execution (`superpowers:executing-plans`). Steps use checkboxes.

**Goal:** warn on mainnet-beta, in the Deploy stage and in the `deploy`
command, that the deploy moves real SOL through the browser-held Playground
wallet, and recommend deploying from the user's own machine.

**Architecture:** one module in `commands/deploy` owns the wording and the
cluster check; the command prints it, `BaseDeploy` renders it from its
`cluster` prop.

**Spec:** `../specs/mainnet-deploy-warning/spec.md`, `../design.md`.

## Global Constraints

- Wording (exact, both places): "Mainnet uses real SOL. This deploy moves
  SOL through the Playground wallet, whose key is kept in this browser where a
  malicious script could read it. For a program that matters, deploy from
  your own machine with the Solana CLI or Anchor."
- Callout: `Callout variant="warning"` from `@/shared/ui/callout`,
  `aria-label="Mainnet deploy warning"`; never disables Deploy.
- Cluster value is exactly `"mainnet-beta"`.

## Review Focus

- `cluster === null` (endpoint not yet read): no callout.
- A custom endpoint that resolves to mainnet-beta by genesis hash: the
  check is on the cluster name, so it warns too (no extra test: same prop).
- Built and unbuilt stage both show it (unit test covers unbuilt + built).
- Deploy button stays enabled on mainnet (unit test asserts it).
- Callout sits before the actions footer, so the footer stays last
  (existing `lastIsActions` test keeps passing).
