# Sign-in card for a refused tutorial build: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax.

**Goal:** a tutorial build that `/api/build-server` refuses with `reason: "signed-out"` shows a "Sign in to build" card whose primary is "Sign in with GitHub", then "Build" once signed in.

**Architecture:** a new `BuildFailure` reason `signed_out` flows runner → persistence → reducer → result card. Detection is one predicate in the legacy root; the widget reads the session.

**Tech Stack:** TypeScript, React 19, vitest (in-source blocks and `*.test.tsx`).

**Spec:** `openspec/changes/tutorial-build-sign-in/specs/tutorial-runs/spec.md`, `design.md`.

## Global Constraints

- Copy, verbatim: head `Sign in to build`; line `Builds run on Playground's build server, which needs a GitHub sign-in. Your code stays in this browser.`; buttons `Sign in with GitHub` / `Build`; build-and-deploy line `Sign in with GitHub to build.`
- A feature never imports another feature: `features/tutorial-conversation` does not import `@/features/auth`.
- No new telemetry event; outcome stays `failed`.
- `undefined` over `null` in new code; no nested ternaries; `AsyncButton`/clicks catch into `reportButtonFailure`.

## Review Focus

- Session read not answered yet (`useSignedIn` → `undefined`): the card shows "Sign in with GitHub" (treat as signed out), never flashes "Build" then flips. Test in `turns.test.tsx`/card test with `signedIn: false`.
- Popup closed or blocked: `PgSession.signIn` rejects; the button reports through `reportButtonFailure("sign in")` and the card stays. Covered by the existing `reportButtonFailure` toast; no auto-build.
- Reload with a saved `signed_out` result: `parseResult` must not rewrite it to `compiler`. Test in `progress.ts`.
- ⌘↵ on the live sign-in card: signed in → runs the act; signed out → signs in, never Explain. Test in `TutorialConversation.test.tsx`.
- Build-and-deploy refused for sign-in: deploy card message `Sign in with GitHub to build.` Test in `real-deploy.ts` block if one exists, else by `buildFailureOf` there.

- Modify: `features/tutorial-conversation/model/progress.ts` — `BuildFailure = "compiler" | "unreachable" | "signed_out"`; `isSignedOut(r: RunResult): boolean` beside `isUnreachable`; `parseResult` keeps `signed_out`. Export `isSignedOut` from the slice's `index.ts`.
- Modify: `runners/build.ts` — on `isSignInRefusalError(e)`: `log.info`, return `{act:"build", ok:false, seconds, reason:"signed_out", error:null, log: message}`.
- Modify: `reducer.ts` Explain guard — no-op for `isSignedOut` as for `isUnreachable`.
- Modify: `runners/real-deploy.ts` `buildFailureOf` — `signed_out` → `Sign in with GitHub to build.`
- Tests: `runners/build.test.ts` ("returns signed_out, not compiler, when the server asks for sign-in"; error built as `Object.assign(new Error("Sign in with GitHub to build."), {reason: "signed-out"})`), `progress.ts` block ("keeps a signed_out build on load"), `reducer.ts` block (Explain on a signed_out result changes nothing).
