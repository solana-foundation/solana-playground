# 1.1 Status panel per Spec 06

Ticket: HOO-2582. Base: `scope/interface-2`. Mode: inline.

**Success metric (from the ticket):** every Spec 06 status state named in
the ticket is reachable and shows its words and actions on desktop and phone
(RUN-27, RUN-28 of Spec 06's QA plan pass by hand).

## Steps

1. `model/indicators.ts`: `panel` and `retry` on every indicator; AI inputs
   `checking`, `unreachable`, `limit`; the limit line names the local time
   the limit comes back. In-source tests first, watched failing.
2. Assistant store: `limitReachedUntil` (next 00:00 UTC, cleared by another
   backend and by `disconnect`), `markLimitReached`, `defaultProbe` and
   `setDefaultProbe`. In-source tests.
3. Writers: `provider.ts` marks the limit on a capped refusal;
   `probeDefaultBackend` publishes `checking`, `unreachable`, `answered`.
4. `use-status.ts` maps the store into the AI input. Tests in
   `use-status.test.tsx`.
5. UI: `StatusDetail` draws Try again (`AsyncButton`, "Trying…", "Could not
   reach …"); `StatusPanel` is the popover for row and rail and closes on an
   action; row and rail open it by `indicator.panel`; the sheet passes
   `onRetry`. Tests in `BaseStatus.test.tsx`.
6. Wiring: `Status.tsx` retries (cluster `recheck`, hosted model
   `onRetryAi`) and sends `status_retried`; `Flow.tsx` passes
   `onRetryAi`. Test in `Status.test.tsx` through the memory provider.
7. e2e: "A cluster that stops answering" now goes through the panel's
   Change network.
8. Verify: `yarn run check`, the changed e2e spec, screenshots of the row
   panel and the phone sheet (before on `scope/interface-2`, after on the
   branch) through Playwright.

## Gaps decided (sent to Design alignment, accepted 4 Nov)

- A panel only where it adds something; ready, connecting and off act at once.
- "AI ·", not "Assistant ·"; "Try again", not "Retry".
- Limit: "Add an API key"; known from the last refusal in the tab; the line
  says when it comes back in local time.
- "AI · Not responding" (red) with Try again and Add an API key when the
  hosted-model check fails online (from HOO-2577).
