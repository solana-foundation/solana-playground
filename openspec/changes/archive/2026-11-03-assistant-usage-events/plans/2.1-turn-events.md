# Task 2.1: the turn events — implementation plan

> **For agentic workers:** run with superpowers:executing-plans, inline.

**Goal:** `widgets/assistant` reports every turn once as sent and once as
ended, per backend (HOO-1799, the AI-usage part).

**Architecture:** four events in `model/telemetry.ts`; `use-turn.ts` sends
`assistant_turn_sent` from `runTurn` on attempt 0 after `beginTurn`, and one
outcome from `runTurn`'s `try`/`catch` (or from `waitOnBusy`, `resend` and
`stop` for the busy-retry paths). `trackTurnFailure` turns a caught error
into the outcome and sends it.

**Spec:** [../specs/client-v2-assistant-usage/spec.md](../specs/client-v2-assistant-usage/spec.md),
[../design.md](../design.md).

## Success metric (HOO-1799)

In GA4, for any day and any backend, the count of assistant turns sent and
how each ended — answered, failed (with a reason), capped, or stopped — and
every sent turn ends with exactly one outcome event.

## Global constraints

- `provider` is the connection's `ModelProvider` id (`current.id`).
- `reason`: `"provider" | "refusal" | "paused" | "other"`; `status` a number
  or absent. GA4 names ≤ 40 characters, prefix `assistant_`.
- No event parameter carries prompt, reply, tool data, file content or key.
- Existing events and the thread's text do not change.

## Review focus

- A turn the user stops while a tool waits on approval: aborted → no outcome
  besides `stopped`.
- A busy resend that itself fails with a non-busy error: one `failed`, no
  second `sent`.
- An error thrown after `stop()` (aborted, not an `AbortError`): no outcome.
- The empty-response path (`addError` with no throw): reported as answered.
- A failure whose message quotes the prompt: no event holds the prompt.

  `assistant_turn_answered { provider }`,
  `assistant_turn_failed { provider; reason: TurnFailedReason; status?: number }`,

  failed with its reason and status; `isDroppedConnection` → failed
  `provider` no status; else failed `other`.
