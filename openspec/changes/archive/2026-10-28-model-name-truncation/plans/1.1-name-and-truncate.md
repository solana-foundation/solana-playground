# Name and truncate the model: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The head and the composer name the model in use; a long name ends in "…" with a tooltip when cut; the no-model state is pinned by tests.

**Architecture:** A pure `headLabel(shown)` turns `ModelShown` into a `HeadLabel` union (plain text, or lead, model, tail); an `OverflowTooltip` opens the design system's `Tooltip` only when its marked text overflows. Both the head and `BaseModelMenu` use it.

**Tech Stack:** React, Radix Tooltip/DropdownMenu via `@/shared/ui`, Tailwind 4, vitest + Testing Library.

**Spec:** `openspec/changes/model-name-truncation/specs/assistant-model-name/spec.md`, `design.md`.

## Global Constraints

- Copy: "Assistant · {model} · hosted", "{model} · your {provider} key", "Assistant"; providers Anthropic, OpenAI, OpenRouter, Gemini.
- Composer model button at most 12rem (`max-w-48`).
- `shared/ui` is not edited. Telemetry unchanged.
- Existing aria-labels stay ("More", "Checking the model…", "Message the assistant").

## Review Focus

- A name that fits never opens a tooltip (stubbed `scrollWidth == clientWidth`).
- Keyboard focus on a cut model button opens the tooltip, as hover does.
- The tooltip on the model button must not block the menu opening on click.
- `checking` and `none` read "Assistant" in the head, never "Default model".
- A keyed connection with no model of its own ("Default model" label) still reads "· your … key".
