# Plan 1.1: titled off row and head status (HOO-2577)

Goal: each off reason gets a title; no-key gets Try again; the head shows
`#assistant-status` ("Off" / "Not responding") from the same derivation as the row.

Success metric (from the ticket): a person who opens the assistant with no model
reads, before typing, a titled reason and a way in on every off reason; with no
hosted model, Try again re-asks `GET /api/ai/status` without a reload.

## Steps

1. **Tests first** (`AssistantComposer.test.tsx`): titles per reason; no-key shows
   Try again after Add an API key and calls the retry. Run, see them fail.
2. `BaseAiOffRow`: `title` per reason in `REASONS`, `CalloutTitle` over
   `CalloutDescription`; no-key action list gains retry as secondary. Keep
   `role="status"` and `#assistant-ai-off`. Run step 1 green.
3. **Tests first** (`BaseAssistantHead.test.tsx`): an `off` prop draws
   `#assistant-status` with StatusDot + word; nothing when `undefined`.
4. `BaseAssistantHead`: the `off` prop (the reason, or `undefined`) mapped by a
   `Record` to word + dot variant: "Off" `idle`, "Not responding" `error`.
5. Move `useSignedIn` into `widgets/assistant/model/use-signed-in.ts`;
   `Assistant` runs the pure `aiOff` over the same inputs as the composer and
   passes the reason to the head. `Assistant.test.tsx` covers each reason, a
   sign-in clearing it, and a kept key hiding it.
6. e2e `assistant-ai-gate.e2e.spec.ts`: titles, Try again on no-key, head status.
7. Verify: `yarn run check`, the e2e spec, lint delta, screenshots (before from
   `origin/scope/ai-rail`, after from this branch) of the three reasons.
