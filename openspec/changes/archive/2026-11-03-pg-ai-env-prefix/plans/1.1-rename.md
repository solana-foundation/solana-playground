# PG_AI_ env prefix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The assistant's thirteen server variables are read as `PG_AI_*`, with `AGENT_*` still working as a deprecated fallback.

**Architecture:** One helper in `server-env.mjs` resolves a setting's name (new first, old only when the new one is absent) and warns once per old name; `agentEnv` and `readProviders` go through it. `check-agent-env` applies the same rule to the key. Everything else is text.

**Tech Stack:** Node ESM (`.mjs`), `node --test`, vitest for `agent.integration.spec.ts`.

**Spec:** `openspec/changes/pg-ai-env-prefix/specs/assistant-server-env/spec.md`, `design.md`

## Global Constraints

- Prefix `PG_AI_`; suffixes and defaults unchanged.
- Fallback only when `process.env.PG_AI_<NAME> === undefined`; an empty new name does not fall back.
- One `console.warn` per old name per process, naming old and new variable.
- `AGENT_TIERS` and the `features/agent` slice keep their names.
- Commits: Conventional Commits, `(client-v2)` scope, no attribution lines.

## Review Focus

- `AGENT_BASE_URL` is read twice per call (`BASE_URL`, `PROVIDERS`): still one warning. Covered by the warn-once test calling `agentEnv()` twice with only old names.
- `PG_AI_PROVIDERS=""` with an old `AGENT_PROVIDERS=baseten` set: new empty wins, no restriction. Test in Task 1.
- A local `vercel build` pulls a Secret as `""`: `PG_AI_API_KEY=""` locally still passes the check. Test in Task 2.
- A developer's `.env` with only old names: `yarn test-api` cases clear both name sets in `beforeEach`, or the old `.env` leaks into new-name tests. Task 1 and 3.
- Dev server log noise: one line per old name, not per request. Same test as the first line.
