# Definition v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans
> (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** A conversation tutorial is one `tutorial.json` that a schema and a
check command validate by path, and that the catalog lists with "n of m"
progress; Hello Anchor is the first one.

**Architecture:** The definition's types, its check (Ajv over
`tutorial.schema.json`, then the semantic rules) and its loader live in the
`entities/tutorial` slice, so the progress hook beside them can read a
definition without an entity-to-entity import. `scripts/generate-tutorials.mjs`
writes `src/tutorials/_definitions/generated.ts`, a static import of every
`src/tutorials/<slug>/tutorial.json`; `src/tutorials/definitions.ts` hands that
map to the loader and turns each accepted definition into a `TutorialData`.
`yarn tutorial:check` runs the same check through `tsx`.

**Tech Stack:** TypeScript, Ajv 8 (draft-07, already in the lockfile as a
transitive dependency, added as a direct one), tsx, vitest in-source blocks,
`node --test` for the command.

**Spec:** `openspec/changes/tutorial-flow-v2/specs/tutorial-definition/spec.md`
(requirements 1, 2, 3 and 5; requirement 4, `AUTHORING.md`, is task 1.2).

## Global Constraints

- Definition path: `client-v2/src/tutorials/<slug>/tutorial.json`; schema:
  `client-v2/src/tutorials/tutorial.schema.json`.
- One to six steps; an `ask` has exactly three options.
- Error line: `<json path>: <what was expected>, found <what was found>`, path
  written `steps[1].beats[3].why[2]`; exit code 1 on any error.
- The missing-reason error reads exactly
  `steps[1].beats[3].why[2]: a wrong option needs a reason, found null`.
- `yarn run check` runs `yarn tutorial:check`.
- Rejected at runtime: not listed, one `log.error` with the slug and the first
  error, one `tutorial_definition_rejected` with `tutorial` (slug) and `errors`
  (integer from 1).
- Card progress for a definition: "<passed> of <m>" while started, the check
  once the finish card has shown.
- Tutorials without a definition keep upstream's pages unchanged.
- Conventional Commits, scope `client-v2`, ticket in the subject.

## Decisions this plan takes

- **Text fields** are a string, or `{ "text", "phone" }` for a shorter phone
  variant.
- **Files** at a step's start and target are maps `path -> content`; `file` is
  the step's main file.
- **Goal** is `{ "kind": "build", "instructions"?: [..] }`, `{ "kind": "deploy" }`
  or `{ "kind": "call", "instruction", "args"?: [..], "log"?: "<regex>" }`
  (design D5). An instruction "defined by a target" is a `fn <name>` in any
  step's target file.
- **Block in target** compares trimmed, non-empty lines in a row, so
  indentation and blank lines do not matter.
- **Docs** are `{ "title", "url", "file" }`: `file` names a Markdown page in
  the tutorial's `docs/` folder, and `url` the page on its own site. The
  command reads the folder and fails a missing page and any link in a page
  that is not `https` (code blocks and spans aside); the app's loader has no
  folder and skips those two rules. Hello Anchor's four pages are task 2.3's.
- **Read only** is a step's `readOnly: [<path>...]`; each path is in the
  step's start or target.
- **No scripted matches, no win stats** (Almaz, 28 Oct): the schema refuses
  step `matches`, step `chips`/`errorChips` (no chips row during the lesson)
  and a chip's `pattern`; only the finish chips keep their answers. The intro is `{ "promise", "log", "files" }`.
- **Card meta line** "<level> · <framework>" is `tutorialCaption` in the flat
  catalog, unchanged; the minutes stay off the card.
- **Ids**: beat ids are unique across every step's `beats` and `onFail`; step
  ids are unique too, since saved progress names steps by id.
- **Saved progress the card reads** (the contract 3.1 writes):
  `.workspace/tutorial-storage.json` key `conversation` =
  `{ "version": 1, "passed": [<step id>...], "finishedAt": <ms> | null }`.
  Without that key a definition tutorial still on the old lesson reads its
  page progress as today, until 7.1 removes the old lesson.
- **Opening** a definition tutorial still imports its folder's React component
  (Hello Anchor's old lesson); 2.1 replaces that with the conversation.
- **Fixtures** for the two broken scenarios live in
  `src/tutorials/__tests__/<name>/tutorial.json`; `generate-exports` already
  skips `__tests__`, the check command skips `_`-prefixed folders unless given
  the path.

## Review Focus

- A `tutorial.json` that is not JSON: the check prints
  `<slug>/tutorial.json: not JSON, <parser message>` and exits 1 (Task 2).
- A definition folder with no `index.ts`: `generate-exports` must not export it,
  or the build breaks on `export * from "./<slug>"` (Task 3).
- The same slug as an existing custom tutorial (Hello Anchor): the catalog
  lists it once, from the definition (Task 3).
- Saved progress naming a step the definition no longer has: counted only if
  the id still exists, never above m (Task 4).
- An anyOf/oneOf failure (a text that is neither string nor `{text, phone}`):
  one line for the field, not one per branch (Task 1).

**Files:**

- Create: `client-v2/src/entities/tutorial/model/definition/types.ts`
- Create: `client-v2/src/entities/tutorial/model/definition/check.ts` (in-source tests)
- Modify: `client-v2/package.json` (`ajv` dependency)

**Interfaces:**

- Produces: `type TutorialDefinition`, `Step`, `Beat`, `Ask`, `ActBeat`,
  `Goal`, `Win`, `Chip`, `Text`; `checkDefinition(json: unknown, known:
  ReadonlySet<string>): DefinitionError[]` where
  `DefinitionError = { path: string; message: string }` and
  `formatError(e): string` gives `"<path>: <message>"`. The third argument is
  `{ slug?, docs? }`, `docs` the `docs/` Markdown by file name.

- [ ] Write the failing tests in `check.ts`'s block: a minimal valid two-step
      definition has no errors; `why[2]` null on a wrong option gives
      `steps[1].beats[3].why[2]: a wrong option needs a reason, found null`;
      `answer: 3` gives `...answer: the right option is 0, 1 or 2, found 3`;
      a write block missing from the target names the beat path and the file;
      a goal instruction no target defines; `finish.next` not in `known`;
      a duplicate beat id names both paths; a missing `title` gives
      `steps[0]: needs "title", found none`; a text that is a number gives one
      line for that field.
- [ ] Run `yarn test-unit src/entities/tutorial/model/definition/check.ts`: FAIL.
- [ ] Write the schema (draft-07, `additionalProperties: false` throughout,
      beats discriminated on `kind`) and the types; implement `checkDefinition`
      (Ajv `allErrors`, `discriminator`), the Ajv-to-path formatter (one line
      per anyOf/oneOf failure), then the semantic rules only when the schema
      passes.
- [ ] Run the tests: PASS. Commit
      `feat(client-v2): tutorial definition schema and check (HOO-1792)`.
