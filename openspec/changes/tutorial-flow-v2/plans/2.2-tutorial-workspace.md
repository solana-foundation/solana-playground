# Tutorial Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans
> (inline) to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax for tracking.

**Goal:** The right side of a tutorial's frame reads as the prototype's
workspace: a head of file tabs that never close, the Call slot, Files ⌘E and
Terminal ⌘J; the file tree as a popover off the active tab that can dock; the
terminal bar's tutorial states and its auto-open rules; and the editor's
written, arriving, landing, error and busy lines.

**Architecture:** A new widget, `widgets/tutorial-workspace`, in Base +
connected pairs. Its models are pure and tested in-source: the tab order, the
tree's rows, the tree's keys, the terminal's status line and auto-open rule,
and the Monaco decorations for the line states. `views/flow/Flow.tsx`
composes it into the frame's stage outlet (head on top, docked tree beside the
editor), so the stage and the console keep their outlets and nothing
remounts. The shell gains three things in the frame: the stage render prop
gets the console's open state and setter, the shell's own console auto-opens
(every deploy start, a failed deploy) step aside for the workspace's rules,
and the console panel takes the drawer's sizes and saves no split.

**Spec:** `openspec/changes/tutorial-flow-v2/specs/tutorial-workspace/spec.md`:
"The workspace head holds tabs, Files and Terminal only", "The editor shows
written, landing, error and busy lines", "The file tree opens from the active
tab and can dock", "The terminal bar is always on screen", the ⌘E and ⌘J lines
of "Keyboard paths are listed".

## Sources, and where they differ

The prototype (`origin/almaz/mobile-tutorial-prototype`,
`design-system/src/prototype/tutorial-v2/desktop/Workspace.tsx`,
`WorkspaceTabs.tsx`, `Editor.tsx`, `FileTree.tsx`, `Terminal.tsx`,
`ui/FileTreeList.tsx`, `prototype.css`) wins over the spec delta:

- **Popover width:** the prototype's `w-64` (256 px), not the delta's 240.
- **Landing edge:** dashed `border-strong` grey, as the prototype's code draws
  it (its comment says purple; the code wins).
- **Arrival:** `pg-arrive`: green `rgb(20 241 149 / 0.18)` settling over the
  ground duration, 40 ms a line, resting on a `foreground/25` left border.

Decided here, no source settles it (gaps: decide; sent to Tool - Design
alignment, batch T):

1. **The lesson's Steps column stays in the frame** until the feed (3.3)
   carries steps and Skip. 2.1 left it for 2.2 to replace, but the tree
   carries files only: removing the column now loses Steps and Skip for every
   learner, and CI's lesson specs with them. The tree is the workspace's way
   to files; the column's own Files tab stays until 3.3 removes the column.
2. **The upstream editor tabs are not drawn in the frame**: the head's tabs
   replace them, and two tab rows would read as two editors.
3. **"All tabs" overflow menu: built**, as the prototype has it, shown only
   while the strip hides a tab past its edge (Design alignment, 2 Nov 23:05,
   reversing this plan's first answer).
4. **The terminal drawer is the prototype's**: 240 px open, 120 min, 60 % of
   the workspace at most, in the frame only; the shell's console keeps its
   own 256 outside it (Design alignment, 2 Nov 23:05).
5. **"Deploying · <stage>"** reads "Deploying" alone: the product's deploy
   reports no stages yet.
6. **The line states' data:** this task wires the error line (the failed
   build's first diagnostic in the open file) and busy (a build or deploy
   running). Written, arriving and landing are props the feed (3.3) and the
   question card (HOO-2353) fill from the engine's `Wrote` and `landingFor`.
8. **Ctrl E off a Mac stays the terminal's** end of line; ⌘E on a Mac and
   Ctrl E everywhere else still toggle the tree, from any text field.
7. **"First client run" auto-open** waits for the run act (4.x): the product
   has no client run event yet. Failed build and first deploy open it now.

## Telemetry

Prefix `tutorial_workspace`, logger `tutorial-workspace:<module>`:

- `tutorial_workspace_tree_opened` with `via`: `tab` (the chevron), `button`
  (Files), `key` (⌘E);
- `tutorial_workspace_tree_docked` with `docked`;
- `tutorial_workspace_file_opened` with `via`: `tab` or `tree`;
- `tutorial_workspace_terminal_opened` when the drawer opens by itself, with
  `reason`: `build_failed` or `first_deploy`.

The console's own toggles are the shell's `layout_*` events already.

## Global constraints

- Head 44 px (`h-11`), the chat head's line. Tabs in the project's order
  (`src/lib.rs`, then `client/client.ts`, then the rest), named by their base
  name, no close button. The active tab carries the chevron,
  `aria-label="Files"`, `aria-haspopup="dialog"`, `aria-expanded`.
- Right end: the Call slot (absent until 4.4 passes it), a rule, Files and
  Terminal as 18 px glyph buttons with a tooltip "<name> <key>", both
  `aria-pressed` while open. No Build, Deploy or Run.
- Tree: folders in their first file's order, files indented 20 px a level,
  rows 28 px, 13 px. Open file marked (`aria-selected`), the live step's file
  a purple dot, a file a later step creates disabled with "Created in step n".
  No `tests` folder. ↑↓ move, Enter opens and closes, Esc closes and returns
  focus to the chevron. The pin shows only from 1100 px of workspace; docked,
  the tree is 220 px left of the editor, the state saved per tutorial.
- Terminal bar 28 px (`BOTTOM_BAR_PX`) with dot and text: "Ready",
  "Building", "Build successful · IDL: n instruction(s) · names", "Build
  failed · line n", "Deploying", "Deployed", "Deploy failed", amber "<file>
  changed since the last deploy". Empty drawer: "Nothing run yet. Builds,
  deploys and calls print here."
- Line states as Monaco decorations; the ghost text is injected text or a
  view zone, never in the model. Reduced motion: no arrival, no squiggle draw.
