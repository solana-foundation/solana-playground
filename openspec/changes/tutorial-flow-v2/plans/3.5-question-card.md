# 3.5 The question card (HOO-2353)

Built on task 2.2 (HOO-2349): its `TutorialWorkspace` takes `marks` and
draws the landing and written lines.

## Success metric

Most learners answer each question by the second try. Check:
`tutorial_question_answered`, the share of `first_try` plus `retry`, over the
first week after Breakpoint.

## Sources

- Look: the prototype's `ui/turns/AskCard.tsx` (`fb4b8e9ee`), 1:1.
- Behaviour: `tutorial-conversation` spec, "A question writes the code on a
  right pick", "The conversation is measured".
- The engine (task 3.1) already resolves picks, hints, skips, `typeIt` and
  `edit`; the card only dispatches.

## Design gaps

None open. The record's "Q<n>" counts the tutorial's `Question` asks in
order (the prototype's `ask.n`); a `Fix it` ask reads "Fix".

The spec's scenario "A wrong pick, then the right one" presses 2 then 1, but
Hello Anchor's right option is the second (`msg!`) and `println!` the first.
The scenario is corrected to "presses 1, then 2" in this PR.

## Tasks

1. **Engine: `tutorial_question_answered`.** `reduce` compares each ask's
   resolution before and after the action; one that left `open` emits the
   event with `result` (`first_try`, `retry`, `typed`, `skipped`,
   `call_panel`) and `attempts` (picks for a pick; wrong picks + 1 otherwise,
   at most 3). Declared on `entities/tutorial`'s tracker. Tests in the
   reducer's block: wrong then right gives `retry`/2; Skip; typed key line;
   a Call panel pass; a question counts once, whatever follows it. Start
   over and a step's Reset open a question again, so a re-answer counts
   again.
2. **`BaseQuestionCard`** (widgets/tutorial-conversation/ui), from the
   prototype: ring, title, three radio rows, the right pick's green square and
   500 ms hold before `onPick`, the wrong pick's red X, shake, `aria-disabled`,
   "Not quite." and its reason via `aria-describedby`, focus to the next
   pickable row, the last row outlined after two wrong, foot buttons. Keys
   1-3, ↑↓, Enter/Space (native button), H, S while it is live and no text
   field has focus. Focus on arrival, `preventScroll`.
3. **`BaseQuestionRecord`**: the one-line button and its expansion. Replaces
   `AskStandIn`; `QUALIFIER` moves with it.
4. **Wiring** (`TutorialConversation`, `Flow`): "Type it myself" dispatches
   `typeIt`; a focus request opens the file and puts the caret on the landing
   line (`landingFor`) or the given line; the stage editor's content changes
   for lesson files dispatch `edit` (debounced); the feed hands the workspace
   `marks`: the open question's landing, the last wrote card's lines arriving.
5. **Tests**: component test of the corrected scenario (keys 1 then 2: "Not
   quite." with the reason, the record "· 2nd try", expand shows three rows),
   H/S keys, the typed-by-hand path through the engine (`edit` with the key
   line resolves "· typed by you" and queues the rest of the block).
6. Verify: `yarn run check`; the tutorial e2e specs this PR changes; screenshots
   before/after of the open card, a wrong pick, the record open.
