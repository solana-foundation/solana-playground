# 7.2 No act record right above its own result card (HOO-2543)

Source: `design-system/src/prototype/tutorial-v2` at `f7d42bf2e`, SPEC 6.5 "Record"
and `ui/Conversation.tsx` (`chat[i + 1]?.kind === "result"`).

1. `view()` drops an ended act whose next shown turn is its own result. This
   replaces the faucet's special case, which the rule covers.
2. A run the step's goal refused posts `<beat>:retry`, a live card with the act's
   own button, only once the step has nothing left to do. Ended acts are never
   live, so nothing live can vanish with the record. ⌘↵, the pill and a call's
   fields all work through the act card.
3. `BaseFeed` scrolls on a new last entry, not on the count: a result card that
   replaces its act leaves the count unchanged.
4. Time, where the card has details: already in the landed build, deploy and tx
   cards; added to a failed call's or run's details, when it has a log to open. A failed build or deploy says
   no time, as the prototype.
5. Tests first: `view.ts`, `goals.ts`, `BaseFeed.test.tsx`, `turns.test.tsx`. Gate: `yarn run check` and CI's e2e.

## Design gaps

Settled with Design alignment, 5 Nov:

- A failed build or deploy shows no time, as the prototype.
- A failed call or run opens its details with "Your call ran in 0.9 s."
- An act's own `record` line goes unseen when its result is right under it.
- A goal-refused run gets one plain say between the result and the live card,
  worded by Design alignment and built from the goal (`goalGap`, `whyRefused`).
