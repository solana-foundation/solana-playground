# Docs as Read-Only Tabs

**Goal:** a tutorial's few doc pages show as a `Docs` folder at the end of
the workspace's tree. They open as read-only tabs beside the file tabs. Each
doc tab closes; file tabs do not. A page opens from the tree, or from a link
to it in the assistant's answer, and never opens by itself (HOO-2381).

**Spec:** `tutorial-workspace`, "Docs open as read-only tabs" and the tree's
`Docs` folder; `tutorial-definition`, the docs list and the check's
missing-doc rule; `tutorial-phone`, docs in Code's file list; design D10.

## What 1.1 already gave

Task 1.1 landed most of the definition side:

- `docs` in `tutorial.schema.json` and the `Doc` type (title, `https` url,
  file);
- the check's rules: a doc whose Markdown file is missing, a link that is
  not `https`, and a file listed twice;
- the CLI reading `docs/`, with a test for the missing file.

The assistant's tutorial context (`describeTutorial`) already lists the docs
with their addresses, so its answers can link them.

## What this task adds

- **The bundle:** `generate-tutorials.mjs` imports every `docs/*.md` beside
  its `tutorial.json` as raw text. The loader passes each tutorial's pages to
  the check, so a listed page missing from the bundle drops the tutorial at
  runtime, as the CLI fails it. `TutorialData.docPages` carries the Markdown
  by file name.
- **Hello Anchor's pages** are copies of the originals the docs list links
  (Natalia, 4 Nov): Anchor's Program Structure and IDL
  (`solana-foundation/anchor`, `docs/content/docs/basics/*.mdx` at
  `a8d7b451d2`) and Solana's Programs and Transactions
  (`solana-foundation/solana-com`, `apps/docs/content/docs/en/core/*/index.mdx`
  at `c381a78b38` and `397267c9e5`). Their MDX is cleaned into our Markdown,
  their wording unchanged (checked word for word against the sources, 4 Nov):
  the frontmatter's title becomes the heading, and on the Anchor pages its
  description the first paragraph, as Anchor's site shows it; a `Callout`
  becomes a blockquote, each `Tab` a bold label with every tab's content
  shown in turn (the site shows one tab at a time), a `Card` a list item
  with its link; images are dropped,
  site-relative links made absolute on the page's own site, and in-page
  `#section` links left as their text, since the check takes `https` links
  only. The pages keep their sites' wording, so markdownlint leaves
  `src/tutorials/*/docs/` out; `yarn tutorial:check` still checks their
  links.
- **Docs are optional, and the browser suite has its own.** A tutorial that
  lists no pages shows no `Docs` folder. Four pages written to test the tabs,
  with their list, are kept under `src/tutorials/__tests__/docs/hello-anchor/`;
  the check's tests read them. Playwright starts the dev server with
  `TUTORIAL_TEST_DOCS=1`, and with it the generator gives a tutorial that
  lists no docs of its own the test pages from `__tests__/docs/<slug>/`, so
  the doc tests keep running should Hello Anchor's list ever go. No other run
  or build sees them.
- **What the assistant is told:** the tutorial context lists the pages as
  "This tutorial's doc pages, which open beside the code", and asks for a
  Markdown link with the address exactly as listed when one covers what it
  explains, and another site only for what none covers (Natalia, 4 Nov).
  Checked with the default model on 4 Nov: before the change, a question
  about `#[program]` got no link; after it, a question on
  `#[derive(Accounts)]` linked Program Structure, and its tab opened.
- **The link:** `entities/tutorial` matches a link to a doc by its page
  (`www.`, a trailing slash, the query and the section aside), never by its
  file name (`docForLink`): the assistant is given the addresses, and a bare
  `idl.md` would open as a broken link where no tab can show it. The entity
  also carries a request (`requestDoc` and `onDocRequest`): the conversation
  widget asks, and the workspace widget shows the page and says whether it
  did. Two widgets may not import each other, so they meet in the entity.
  The answer card catches a press on a doc link and opens the tab instead of
  the site. Where no workspace shows it (the frame is drawn only at its
  widest layout), or with Cmd, Ctrl, Shift or Alt held, the link opens the
  site. When the lesson opens a file or shows a line (`requestCode`), the
  code comes back in front of the page.
- **The tab:** `BaseDocPage` covers the editor and renders the tutorial's
  Markdown read only, under a strip with the title and "Open on <site>" (a
  new tab). The editor stays mounted under it and is `inert` while a page is
  in front. Pressing a file tab or a file in the tree brings the file back,
  and the page keeps its tab.
- **The event:** `tutorial_workspace_doc_opened`, with `doc` and `via`
  (`tree` or `assistant`), counts the ticket's success metric: doc opens from
  the assistant's link.

## Decisions

- **Open doc tabs are kept in `localStorage`, not
  `.workspace/metadata.json`.** The explorer reopens every entry of
  `metadata.json` as a file tab, so an entry for a page would open a file
  that does not exist. The docked tree (2.2) is kept the same way, keyed by
  the tutorial's name. Both stay on the device, as the spec's "local to the
  device" asks. The spec now names `metadata.json` for the open file tab
  only, and the browser's storage for the rest (Natalia, 4 Nov).
- **A reload brings back the page that was in front** (Slava's review, 5 Nov):
  the page in front is kept beside the open doc tabs
  (`tutorial-workspace.front-doc`), and anything that brings the code back
  forgets it. `onDidOpenFile` replays the open file as it subscribes; the
  workspace skips that replay, which would hide the restored page.
- **The phone's Code list is not in this task.** There is no tutorial phone
  layout yet: below the wide frame, a tutorial uses the plain layout, and the
  phone's own layout is HOO-2359 (task 5.x). `TutorialWorkspace` carries a
  `TODO(HOO-2359)` where the list of pages is built.
- **The scenario runs on step 1, not step 2.** Reaching step 2 takes a real
  build. The head and the link behave the same on either step.
