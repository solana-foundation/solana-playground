# 5.1 Tutorial on the phone: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Below the frame's width, a conversation tutorial runs as a phone layout. A header sits on top, with the Chat and Code spaces side by side under it, and the same feed as the desktop.

**Architecture:** The layout shell gains a `phone` part on `TutorialFrameSlot`. When a tutorial is open on the work screen and the viewport is not `wide`, the shell draws `BaseTutorialPhone` in place of the pager or the compact layout. That component holds the header slot and a two-space strip:

- Chat holds the chat body.
- Code holds the stage and console outlets.

The outlets move without remounting, as they do between the frame and the pager. The space state and Code's dot come from a hook in `widgets/tutorial-frame`, which listens to `requestCode` and `requestDoc`. The header and the steps sheet are in `widgets/tutorial-frame`, and step data comes from a new hook in `widgets/tutorial-conversation`. `TutorialWorkspace` takes a `layout` (`"frame" | "phone" | null`). For `"phone"` it draws a Code head (file switcher, Call), a Files sheet with a Docs section and a Call sheet. It keeps the line states and doc pages. The cards read a phone flag from a context, which drops the typing paths and key hints and sizes for touch.

**Tech Stack:** React 19, Tailwind 4, Radix `Sheet` (`shared/ui/sheet.tsx`), vitest + Testing Library.

**Spec:** `openspec/changes/tutorial-flow-v2/specs/tutorial-phone/spec.md`; ticket HOO-2359 as refreshed on 6 Nov, with its four design decisions. Look: Almaz's `origin/almaz/mobile-tutorial-prototype`, `design-system/src/prototype/tutorial-v2/` (`screens/StepScreen.tsx`, `sheets/*`, `ui/StepBar.tsx`).

## Global Constraints

- Phone layout: `useViewport() !== "wide"` (under 1024 px) on the work screen with a tutorial frame. From 768 to 1023 the chat is `max-w-[640px] mx-auto px-8`, and card buttons size to their label (`min-w-60`).
- Header `h-[4.75rem]`, `pb-4 pl-1 pr-4`.
  - Back: an icon button `size-11`, aria "Back to tutorials".
  - Name button: `h-11 flex-1`. Line 1 is the name; line 2 is "{n} steps · {m} min", "Step {n} of {total} · {short}" or "Done · {total} of {total}".
  - Toggle: `h-9 rounded-[10px] px-3` plus a 44 px hit area. It is labelled "Code" (icon `Code`) in Chat and "Chat" (icon `MessageSquare`) in Code.
  - Track: `absolute inset-x-4 bottom-2 grid gap-1`, segments `h-1 rounded-[4px] bg-foreground/[0.12]`, lit with `linear-gradient(90deg,#9945ff,#14f195)`. Before Start, a hairline `h-px bg-border` at bottom 0.
- Sheet chrome: `max-h-[82dvh] rounded-t-2xl bg-surface-panel`, no top border, `shadow-[0_-12px_40px_rgb(0_0_0/0.45)]`, handle `mt-3 h-1 w-9 rounded-full bg-foreground/20`. The Call sheet is `h-[80dvh] max-h-[80dvh]`.
- Steps sheet rows: `min-h-14 rounded-lg px-2 py-2 gap-3`.
  - Each row has a glyph `size-5`, the title, the objective (caption, muted), and "Done" or "Now".
  - The current row is `bg-foreground/[0.06]`; unreached rows are disabled at `opacity-60`.
  - "Start over…" comes after `border-t`: `h-12`, icon `RotateCcw`, only once started.
  - Sheet title: the tutorial's name. Description: "{passed} of {total} steps done. Tap one to read it again."
- Code's dot: `absolute top-1.5 right-1.5 size-1.5 rounded-full bg-brand-purple animate-pulse-dot [animation-iteration-count:2]`. It is set when the conversation's count of `wrote` turns grows while Chat shows, cleared on showing Code, and never shown after the finish.
- Swipe: the strip is `w-[200%]`, translated `0` or `-50%`, `duration-300`. The space out of view is `inert`. A swipe needs `|dx| >= 56` and `|dx| >= 2|dy|`. It is ignored from within 20 px of the left edge and inside an element that scrolls sideways (`scrollWidth > clientWidth` with `overflow-x` auto or scroll).
- Code head: `h-12 border-b pl-2 pr-4`.
  - The file switcher is a button `h-11 rounded-lg px-2`: the filename in `font-mono` and a caret chip `size-[1.375rem] rounded-md bg-surface-hover`.
  - "Call" (the existing `CallButton`) shows only when `PgCallPanel.callable`.
- Files sheet: title "Files", rows `h-11 text-[0.9375rem]`. When a tutorial has docs, the sections are "All files", then "Docs", each under the same caption-sized label.
- Status strip: the console's tutorial bar (`ConsoleDrawer tutorial=`) at Code's foot. Closed, it is `BOTTOM_BAR_PX` tall; open, the console takes `max-h-[42dvh]`.
- Touch: every control is at least 44 px (`h-11`). Option rows are `min-h-12`. There are no `Kbd` hints. Act buttons are full width under their text (`w-full`).
- Phone copy: no "Type it myself", no "I'll fix it myself", no "Open Call". A definition text `{text, phone}` shows `phone`.
- The finish stays a chat card; there is no Finish screen.

## Review Focus

1. **Rotate across 1024.** The editor (Monaco) and the terminal keep their state: the outlets do not remount. Test: the `LayoutShell` test resizes 390 → 1440 → 390 and asserts that the stage node is the same element.
2. **A doc link from the assistant on the phone.** It switches to Code with the page in front, not a new browser tab. Test in task 4: `requestDoc` returns true and the space is `code`.
3. **Swipe inside the editor or a code block.** A horizontal scroll in Monaco or a `pre` must not change space. Test in task 1: a swipe starting in an element that scrolls sideways is ignored.
4. **Back with the steps sheet open.** The sheet closes, no dialog stays over the Tutorials page, and progress is kept. Test in task 3.
5. **Coming back to a tutorial left in Code.** The space starts on Chat for each tutorial entered, so a learner never lands on an empty editor before Start. Test in task 2.
