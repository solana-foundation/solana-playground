## Design gaps (settled by Almaz's tutorial-v2 prototype, 3 Nov)

No source in the DS prototype or the designers' spec draws the run or call
result card. Design alignment found it in Almaz's tutorial-v2 prototype
(`ResultCard`, "Tx ok" and the failure card), which ranks above the
designers' spec, and the card follows it:

1. **Landed:** "Confirmed", the instruction in mono as meta, the program's
   line ("Program log: …") on a green rule in view. Behind the head's
   chevron: one sentence ("client.ts ran in {s} and called `hello`. It used
   {n} compute units, and the fee was {fee} test SOL from your wallet."),
   then Copy signature, Explorer ↗ (devnet) and Log.
2. **Failed:** red card, "Run failed" / "Call failed", meta "NotEnoughEnergy
   · error 6000" for a program error, else the plain reason; the error line
   on a red rule and the whole reason under it; the log behind the chevron.
   The prototype's "Explain the error" and "I'll fix it myself" arrive with
   task 3.6, the assistant.
3. **A run that sent nothing:** not red: Eye, "No transaction", "client.ts
   sent none · see the terminal" (`reason: "no_transaction"`).
4. **Funding:** under 0.5 SOL the wallet is topped up as a first "Funding
   your wallet" stage; a refused airdrop with the wallet unable to pay a fee
   is `no_funds` with the faucet card's facts (the card itself is task 4.2's).

Not done: an older result card folding to its head.

## Steps

1. `RunInput.log`: the step's `call` goal's log pattern, set by the
   reducer's `act` case, so the card shows the line the goal judges.
2. `progress.ts`: `Receipt` (#248's shape plus `computeUnits`) and
   `receipt?` on a landed run or call; on a failed one `reason?:
   "no_wallet" | "no_transaction"`, or `reason: "no_funds"` with `funding`;
   `outcomeOf` reads the first two kinds.
3. `runners/transactions.ts` (pure): the line picked, an Anchor error read
   into a `Refusal`, the receipt, every transaction folded into one result.
4. `runners/capture.ts`: `captureSends` wraps `Connection.prototype`'s
   `sendEncodedTransaction` for the run (one capture at a time), recording
   each signature and each refused send with its simulation log;
   `isRetriedSend` marks the blockhash errors `PgTx.send` retries.
5. `runners/run-call.ts`: the run and call over a port (wallet, funding,
   send, read back, decode), stages, every failure a result.
6. `runners/real-run.ts`: the port over `PgCommand.run` (the editor's Run),
   `PgProgramInteraction.test` (the Test form's sender), `PgTx.confirm`,
   `getTransaction` and Anchor's `BorshInstructionCoder`; plugged into
   `tutorialRunner`, which the frame now passes to the engine.
7. `BaseTxResultCard` beside `BaseResultCard`, which hands it run and call
   results; component tests in `turns.test.tsx`.
8. Hello Anchor's steps 3 and 4 on devnet by hand (Playwright), screenshots.
