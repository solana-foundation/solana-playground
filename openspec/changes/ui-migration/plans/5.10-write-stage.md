# Write stage Implementation Plan

> **Executed.** Task 5.10 shipped from this plan. The code is authoritative
> where they differ. Review rounds changed it in these ways:
> - Clear is named "Clear", so "Console" stays the only match for its button.
> - The focus guard covers only the open the editor makes as it mounts.
> - The tab root is `role="presentation"`, and `#tabs` wraps the tablist
>   with Wallet beside it.
> - The tab drag state is one `drag` field.
> - The stepper folds below a measured `STEPPER_FULL_WIDTH_PX`
>   (`views/flow/header/stepper-width.ts`).
> - The terminal `Wrapper` sets no `font-family`: xterm keeps
>   `theme.font.code.family`.
> - `isTypingElsewhere(outside, active)` takes the editor first; the focused
>   element is second and defaults to `document.activeElement`.
> - `Dnd.Sortable` no longer spreads the sortable's `attributes` onto an
>   item, so a tab root is not focusable.
> - The close button stops `mousedown`, so a press on it never starts a drag.

**Goal:** The Write stage takes the design system's look: editor tabs from
`EditorTabs`, the console from `ConsoleDrawer`, the terminal in the
`Terminal` well. The editor stops taking focus from a field the user is
typing in, and the stage bar's stepper folds to letters by the bar's width,
not the window's.

**Architecture:** Every piece follows the UI move rule (`client-v2/CLAUDE.md`):
`Tabs`, `Tab` and `ConsoleDrawer` import other UI of ours, so a `Base` pair is
extracted beside each and the old component stays as the connected wrapper.
The layout shell keeps owning the console's height and ⌘J; the design
system's drawer only draws. xterm stays the terminal's engine; only its
theme and its host's styles change.

**Tech Stack:** React 19, Tailwind 4 utilities, design-system components
installed with `yarn ds-add`, `@dnd-kit` through the legacy `Dnd.Sortable`,
xterm, Monaco, vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/tasks.md` 5.10 (HOO-2065, with its
comments: focus on a late Monaco mount, the stepper breakpoint);
`specs/client-v2-layout/spec.md`; the prototype
https://solana-playground-ds.vercel.app/#app and `design-system/src/ds/pg-blocks.tsx`
(blocks `console-drawer`, `terminal`, `editor-tabs`) as reference.

## Review Focus

- The console folded to 28 px by the shell while the design system's
  content has its own `h-64` / `h-[45dvh]` heights: the well must fill the
  panel at any height, on a phone too, and show nothing when folded.
- ⌘J pressed once must toggle once: the drawer's own hotkey is off, the
  shell's stays.
- Clicking Clear or the chevron inside the strip must not toggle twice
  (the strip toggles on click, the chevron is its own button).

  focuses the editor: the active element is a tree item, not a text field.
- A tab dragged to reorder must not open or close it; a close click must not
  switch to the tab first.

```tsx
import type { FC, ReactNode } from "react";

import {
  ConsoleDrawer,
  ConsoleDrawerActions,
  ConsoleDrawerBar,
  ConsoleDrawerContent,
  ConsoleDrawerStatus,
} from "@/shared/ui/console-drawer";
import { StatusDot } from "@/shared/ui/status-dot";
import type { ConsoleStatus, ConsoleStatusTone } from "./status";

/** The well's id: the shell's e2e and `aria-controls` find the body by it */
export const CONSOLE_BODY_ID = "flow-console-drawer-body";

const DOT: Record<ConsoleStatusTone, "idle" | "running" | "success" | "error"> = {
  idle: "idle",
  running: "running",
  success: "success",
  error: "error",
};

interface BaseConsoleDrawerProps {
  open: boolean;
  onToggle: () => void;
  onClear: () => void;
  status: ConsoleStatus;
  children?: ReactNode;
}

/**
 * The console under the stage, drawn from the design system's drawer. The
 * layout shell owns its height (folded, it is `BOTTOM_BAR_PX` tall: the
 * strip alone) and ⌘J, so the drawer's own hotkey is off and the well fills
 * whatever height the panel has.
 */
const BaseConsoleDrawer: FC<BaseConsoleDrawerProps> = ({ open, onToggle, onClear, status, children }) => (
  <ConsoleDrawer
    open={open}
    onOpenChange={onToggle}
    hotkey={null}
    contentId={CONSOLE_BODY_ID}
    className="h-full rounded-b-md border border-t-0 border-border bg-surface"
  >
    <ConsoleDrawerBar triggerLabel="Console" className="shrink-0">
      <ConsoleDrawerStatus>
        <StatusDot variant={DOT[status.tone]} />
        <span data-console-label className="font-semibold tracking-wide text-foreground">Console</span>
        {status.text && (
          <span className={status.tone === "error" ? "text-error" : undefined}>{status.text}</span>
        )}
      </ConsoleDrawerStatus>
      <ConsoleDrawerActions>
        <span aria-hidden className="font-mono opacity-60">⌘J</span>
        {open && (
          <button
            type="button"
            aria-label="Clear the console"
            onClick={onClear}
            className="rounded-md px-1.5 py-0.5 hover:bg-surface-hover hover:text-foreground focus-visible:ring-2 focus-visible:ring-ring outline-none"
          >
            Clear
          </button>
        )}
      </ConsoleDrawerActions>
    </ConsoleDrawerBar>
    <ConsoleDrawerContent className="flex h-auto min-h-0 flex-1 flex-col overflow-hidden max-md:data-[state=open]:h-auto">
      {children}
    </ConsoleDrawerContent>
  </ConsoleDrawer>
);

export default BaseConsoleDrawer;
```

```ts
const TEXT_INPUT_TYPES = new Set(["", "text", "search", "url", "email", "password", "number", "tel"]);

/**
 * Whether the user is typing in a field outside `within`. Something that
 * would take focus on its own (the editor opening a file after a late
 * mount) leaves it where it is in that case.
 */
export const isTypingElsewhere = (active: Element | null, within: Element) => {
  if (!active || within.contains(active)) return false;
  if (active instanceof HTMLInputElement) return TEXT_INPUT_TYPES.has(active.type);
  if (active instanceof HTMLTextAreaElement || active instanceof HTMLSelectElement) return true;
  return active instanceof HTMLElement && active.isContentEditable;
};
```
