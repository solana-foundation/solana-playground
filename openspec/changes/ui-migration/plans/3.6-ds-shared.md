# 3.6 Design-system components in `shared/ui` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `client-v2/src/shared/ui` holds the stock components the layout shell needs, installed by `yarn ds-add` from the repo's own registry, and no registry item resolves anything from ui.shadcn.com.

**Architecture:** The stock shadcn files already sit in `design-system/src/components/ui/`; they gain registry items, and the three items of ours that named them bare (`button`, `spinner`, `tooltip`) name `@playground/<x>` instead. A `node --test` guard in `client-v2/scripts/` holds the registry to that. `yarn ds-add` then installs the shell set into `shared/ui`. Our own items are not installed: each pulls `@playground/playground-tokens`, whose destination HOO-1802 decides.

**Tech Stack:** shadcn CLI (pinned in `design-system`), `node --test`, vitest + Testing Library, React 19, `react-resizable-panels` v4, Radix.

**Spec:** `openspec/changes/ui-migration/design.md` ("How the design system reaches the code"), task 3.6 in `tasks.md`; ticket HOO-1949.

**Status:** executed; every step below ran, and the work landed as PR #56.

## Global Constraints

- `shared/ui` holds only installed files; a change to one is made in `design-system/` and reinstalled (`client-v2/CLAUDE.md`, "Components").
- Installs come from the repo's registry through `yarn ds-add`; nothing from the design system's public site, and after this task nothing from ui.shadcn.com.
- Do not touch tokens, `utils/theme`, `Monaco.tsx`, `Terminal.tsx`, `Markdown.tsx` (HOO-1802 is working there).
- Do not install any item that pulls `@playground/playground-tokens`.
- `yarn run check` is the gate; the unit test count does not drop below master-2.0@533f0bb8's, compared name for name.
- Commits: Conventional Commits, `(client-v2)` scope, no AI attribution.
- Node 22.20 (`.nvmrc`), yarn 1.x, commands from `client-v2/` via `yarn --cwd client-v2`.

## Review Focus

1. A registry item imports `@/components/ui/<x>` or `@/hooks/<x>` without declaring `@playground/<x>`: the installed file then imports a file that never lands. Pinned by the guard's imports case (Task 1), which since review of PR #56 also checks npm imports against the item's `dependencies` and fails when no import matches at all.
2. A `@playground/<x>` dependency that names no item: the install 404s on the local server. Pinned by the guard's "resolves" case (Task 1).
3. The installed `sidebar` reads `@/hooks/use-mobile`: the CLI must rewrite it to `@/shared/lib/hooks/use-mobile`, or the type check fails. Pinned by `yarn test-types` and the render test (Task 2).
4. Installed shadcn code trips the layer ESLint rules from #49 (nested ternaries, empty catch): `shared/ui` cannot be edited by hand, so the fix is a lint scope, never an edit. Pinned by `yarn lint` (Task 2).
5. Without the token bridge the components have no theme colours: they must still mount and lay out (Sidebar provider, resizable handle drag). The render test pins the mount, the sidebar toggle and the phone-width sheet (Task 2); it stubs `ResizeObserver`, so the handle drag and the layout are pinned by the browser walk alone (Task 4).
