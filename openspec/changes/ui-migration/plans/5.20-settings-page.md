# Settings as a full page (5.20) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the gear overlay (`GearSidebar`) with a settings page that takes the whole window, with a section list and "Back to app", while the app stays mounted beneath it.

**Architecture:** A new widget `widgets/settings-page` (`BaseSettingsPage`, `BaseSettingRow`, `SettingsPage`) is rendered by `Flow` beside `LayoutShell`. While it shows, the shell and the floating wallet are made invisible and inert, never unmounted. The upstream setting controls move whole from `app/Panels/Side/Left/` into the widget first.

**Tech Stack:** React 19, Tailwind 4 utilities, `shared/ui` (Button, AsyncButton, Segmented, Select, Switch), vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "Settings as a full page (5.20)"; `specs/client-v2-layout/spec.md` ("Settings are a page of their own", "The settings page is measured", "The rail's footer"); `specs/client-v2-elements/spec.md` ("The compiler output folds"); `specs/client-v2-controls/spec.md` ("A setting select").

## Global Constraints

- Branch off and PR into `new-face`. Conventional Commits, scope `(client-v2)`. No AI attribution.
- Layers: `app -> widgets -> features -> entities -> shared`; a widget never imports another widget or `app/`.
- `shared/ui` is never hand-edited; nothing new to install (every part used is already in `shared/ui`).
- No empty `catch`; failures through `createLogger("settings-page:<module>")`, `report: true` when the team must hear.
- No nested ternaries. Tests build fixtures without spreads (`AGENTS.md`).
- Kept names: region "Settings", radiogroup "Network", each setting control named by `setting.name`, `data-settings-trigger`, "Change cluster, currently <name>", "Cluster: <name>". New: "Back to app" (replaces "Close settings").
- Sections, in this order and with these titles: Network, Project, Block Explorer, Build, Connection, Editor, Notification, Server, Test UI, UI, Wallet, Experimental.
- Section list shown from `LAYOUT_BREAKPOINTS.phone` (720) up; below it a 60 px bar (`h-phone-bar`) with "Back to app" and the title.
- Telemetry prefix `settings`: `settings_opened {from: "cluster" | "rail" | "menu" | "key"}`, `settings_closed {via: "back" | "escape" | "key"}`, `settings_section_picked {section}`.
- Gate: `yarn run check`, plus only the e2e specs this PR changes, `PORT=<slot from 6> yarn test-e2e e2e/<spec>.e2e.spec.ts`.

## Review Focus

- Escape while a modal opened from the page (Import from GitHub, a Custom value) is up closes the modal only, never the page. Test in Task 4.
- An endpoint the chips do not list (Mainnet Beta, a custom URL): `focus: "network"` lands on the first chip, no chip is checked. Test in Task 4.
- The nav Sheet (720–767 px) and the phone Menu page: opening settings from them still closes the Sheet / leaves the pager, and the page is on top. Existing e2e "Settings on a narrow window" and "⌘, closes the navigation's Sheet" keep passing (Task 6).
- Hiding the shell must not fold a panel or write the `layout` key: e2e asserts the saved layout is unchanged across open/close (Task 6, in "Back to the app keeps the work").
- A trigger removed from the DOM while the page is open (the nav Sheet unmounted its footer): closing must not throw and focus falls back to `document.body` without error. Test in Task 4.

### Task 5: Flow shows the page, the overlay goes

**Files:**
- Modify: `src/views/flow/Flow.tsx`
- Delete: `src/views/flow/settings/GearSidebar.tsx`, `GearSidebar.test.tsx`

**Interfaces:**
- Consumes: `SettingsPage`, `SettingsRequest`, `settingsTelemetry`.
- Flow state: `settings: { open: false } | { open: true; focus: SettingsFocus; returnTo: HTMLElement | null }` (one union, not two `useState`s). `toggleSettings(closeSheet)(request)`: closed → `closeSheet()`, remember `document.activeElement`, open, `settings_opened {from: request.from}`; open → close with `via: "key"` for `from: "key"`, else the same toggle. No unit test: `Flow` needs the explorer, Monaco and the shell to render, so this wiring is proven by Task 6's e2e; the commit body says so.
