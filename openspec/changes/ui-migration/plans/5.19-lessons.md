# Lessons in the new frame (5.19) Implementation Plan

> Superseded in part by `lesson-prototype-polish` (HOO-2262): the readiness
> callout, `readiness*.ts`, `reading.ts` and the reader's footer are gone.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An open lesson shows the design system's compact objective band over the editor, the step rail behind a Steps | Files switch in the files column, and the page as a non-modal dialog inside the stage; on a phone the band is one row.

**Architecture:** As 5.11: `Base*` components beside the connected ones in `src/views/flow/lessons/`, drawing from props alone; the connected wrappers keep reading `PgLesson`, the ledger and readiness exactly as today. The Steps | Files choice moves up to `Flow` (since the 5.26 merge it stays in `LeftPanel`, kept per project by `kept-column.ts`), and `LayoutShell`'s `stage` slot learns to hand the stage a way to open the phone's Files sheet.

**Tech Stack:** React 19, Tailwind 4, design-system parts from `shared/ui` (`objective-band`, `step-rail`, `segmented`, `callout`, `dialog`, `button`, `brand-button`), vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "Lessons (5.19)"; scenarios in `openspec/changes/ui-migration/specs/client-v2-lessons/spec.md`.

## Global Constraints

- Lesson logic does not change: `ledger.ts`, `store.ts`, `verify.ts`, `readiness*.ts`, `band-copy.ts`, `reading.ts` are read, never edited. Amended in review: `store.ts`'s two failure logs move to `createLogger("lessons:store")` with `report: true`, its logic untouched (design.md, "Failures and the files a lesson keeps").
- Kept as they are: `flow-left-tab-steps` / `flow-left-tab-files` ids, `flow-left-tabpanel`, aria-labels "Previous step", "Next step", "Close the page", "Collapse/Expand project panel", "New file", and the copy "Skip this step", "Back to the code", "Mark as read", "Read the page", "Read step n first", "I'm stuck", "Browse gallery".
- `shared/ui` only through `yarn ds-add`; never hand-edited.
- "I'm stuck" (the `assistantLabel` button) is the band's one `BrandButton`; the proving action is an outline `Button`.
- No empty `catch`; a failure logs through `createLogger("lessons:<module>")` with `report: true` when the team must hear of it.
- No nested ternaries; no telemetry (`views/` is a legacy root).
- Tests build fixtures with explicit copies, never spreads (`client-v2/AGENTS.md`).
- Node 22.20 (`.nvmrc`); commands run from `client-v2/`.

## Review Focus

- A step with no `readPage`: the band offers no "Read the page" and the reader is never opened (BaseObjectiveBand test).
- The finished path (`describeStep` null, `describeFinish` set): the band shows "done" and Browse gallery, back still works (BaseObjectiveBand test).
- The reader's page fails to load: the failure line shows, `onLoaded` never fires, the failure is logged (BaseReader test).
- A click outside the reader (files tree, band) does not close it; only Esc, Close and the footer action do (BaseReader test).
- Crossing 720 px with the Files sheet on Steps: the choice survives the remount of `LeftPanel` (LeftPanel test with controlled props; since the 5.26 merge, the kept-column memory and its `keepTab` test).
