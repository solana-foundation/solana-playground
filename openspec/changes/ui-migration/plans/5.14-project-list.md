# The sidebar project list (5.14) Implementation Plan

> Superseded in part by `lesson-prototype-polish` (HOO-2262): lessons are rows
> under Projects; the Lessons group and its step count are gone.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The navigation lists the user's projects and lessons, each with a
menu of Open, Pin, Rename, Duplicate, Export as zip and Delete with letter
keys, replacing the frame's `ProjectSwitcher` (HOO-2069).

**Architecture:** A `BaseProjectList` / `ProjectList` pair in
`widgets/app-nav`, fed by pure helpers in the widget's `model/` (entries,
pins, copy names). `BaseAppNav`'s `switcher` slot becomes `projects` and is
not drawn on the rail. Actions call `PgExplorer`, `PgTutorial` and the legacy
`DeleteWorkspace` / `ExportWorkspace` modals; `ExportWorkspace` and
`PgFramework.exportWorkspace` take a workspace name.

**Tech Stack:** React 19, Tailwind 4, the installed `shared/ui` parts
(`sidebar`, `dropdown-menu`, `input`), `lucide-react`, vitest +
Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "The project list
(5.14)"; `openspec/changes/ui-migration/specs/client-v2-layout/spec.md`,
requirements "The navigation lists the projects" and "The project list is
measured".

> **Executed (2026-10-16, PR #89); design.md "The project list (5.14)"
> describes what shipped and wins over the snippets below.** Shipped
> differently: the copy is "<name> copy" (a workspace name allows no
> parentheses); failure toasts are named `project-<action>-failed`; a rename

`project-entries.ts`:

```ts
export interface ProjectEntry {
  name: string;
  /** The stable workspace id pins key on; `null` before the explorer has one */
  id: string | null;
  isLesson: boolean;
  /** e.g. "3 of 4" or "done" for a lesson; `null` for a project */
  progress: string | null;
  pinned: boolean;
}

/**
 * The navigation's two groups. Lessons and projects are apart because they
 * open differently (`PgTutorial.open` restores a lesson's route and page) and
 * a lesson cannot be renamed: it is recognised by its workspace name.
 * Pinned entries lead their group; otherwise the explorer's order stands.
 */
export const listProjects = (
  names: readonly string[],
  deps: {
    idOf: (name: string) => string | undefined;
    isLesson: (name: string) => boolean;
    progressOf: (name: string) => string | null;
  },
  pins: readonly string[]
) => {
  const projects: ProjectEntry[] = [];
  const lessons: ProjectEntry[] = [];
  for (const name of names) {
    const id = deps.idOf(name) ?? null;
    const isLesson = deps.isLesson(name);
    const entry: ProjectEntry = {
      name,
      id,
      isLesson,
      progress: isLesson ? deps.progressOf(name) : null,
      pinned: id !== null && pins.includes(id),
    };
    (isLesson ? lessons : projects).push(entry);
  }
  const pinnedFirst = (list: ProjectEntry[]) => [
    ...list.filter((e) => e.pinned),
    ...list.filter((e) => !e.pinned),
  ];
  return { projects: pinnedFirst(projects), lessons: pinnedFirst(lessons) };
};
```

`pins.ts`:

```ts
import { createLogger } from "@/shared/lib/logger";

const log = createLogger("app-nav:pins");

/** Pinned workspace ids, on this device only (syncing them is HOO-2121) */
export const PINS_KEY = "nav.pins";

const isIdList = (value: unknown): value is string[] =>
  Array.isArray(value) && value.every((v) => typeof v === "string");

/** No value is no pins; a value that is not a list of ids is no pins, logged */
export const readPins = (storage: Storage = localStorage): string[] => {
  let raw: string | null;
  try {
    raw = storage.getItem(PINS_KEY);
  } catch (e) {
    log.warn("pins unreadable: storage unavailable", { context: { e } });
    return [];
  }
  if (raw === null) return [];
  try {
    const value: unknown = JSON.parse(raw);
    if (isIdList(value)) return value;
  } catch {
    // Falls through to the warning below: a corrupt value reads as no pins
  }
  log.warn("pins unreadable: not a list of ids");
  return [];
};

export const writePins = (
  ids: readonly string[],
  storage: Storage = localStorage
) => {
  try {
    storage.setItem(PINS_KEY, JSON.stringify(ids));
  } catch (e) {
    log.error(e, { report: true });
    throw e;
  }
};

export const togglePin = (pins: readonly string[], id: string) =>
  pins.includes(id) ? pins.filter((p) => p !== id) : [...pins, id];

export const prunePins = (pins: readonly string[], liveIds: readonly string[]) =>
  pins.filter((p) => liveIds.includes(p));
```

The bare `catch` above is not empty in effect but must carry its comment;

`workspace-files.ts`:

```ts
import type { PgFs } from "@/utils/explorer/fs";
import type { TupleFiles } from "@/utils/types";

type Fs = Pick<typeof PgFs, "readDir" | "getMetadata" | "readToString">;

/**
 * A workspace's files as full paths, read from the store. `.workspace/` is
 * left out: its `program-info.json` holds the program keypair, and a copy
 * holding it would deploy over the original's program.
 */
export const readWorkspaceFiles = async (name: string, fs: Fs) => {
  const root = `/${name}`;
  const files: TupleFiles = [];
  const walk = async (dir: string) => {
    for (const item of await fs.readDir(dir)) {
      const path = `${dir}/${item}`;
      if (path === `${root}/.workspace`) continue;
      if ((await fs.getMetadata(path)).isFile()) {
        files.push([path, await fs.readToString(path)]);
      } else {
        await walk(path);
      }
    }
  };
  await walk(root);
  return files;
};

export const rebaseFiles = (files: TupleFiles, from: string, to: string) =>
  files.map(
    ([path, content]) =>
      [`/${to}${path.slice(from.length + 1)}`, content] as [string, string]
  );
```
