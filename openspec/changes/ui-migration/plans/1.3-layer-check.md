# Layer check implementation plan (ui-migration 1.3, HOO-1859)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an import that breaks the layer rule fails `yarn lint`, `yarn run check`,
CI and the production build, with a message that names the rule.

**Architecture:** `eslint-plugin-boundaries` 7 in `client-v2/eslint-layers.js`, which
`package.json` `eslintConfig` extends (a module, so the exception carries a comment).
`yarn lint` and the dev server read it through `eslintConfig`. The production build
drops CRA's ESLint plugin to save memory (`craco.config.js`, `BUILD_ONLY_CHECKS`), so
`build:bundle` and `build-fast` run `yarn lint:layers` before `craco build` instead,
in a process of its own that ends before webpack starts.

**Tech stack:** ESLint 8.40 (CRA 5), `eslint-plugin-boundaries` 7.2.0,
`eslint-import-resolver-typescript` 3.10 (for `@/`), `node --test`.

**Spec:** `openspec/changes/ui-migration/specs/client-v2-layers/spec.md`
(requirements "New code sits in five layers", "A slice is entered through its door",
"The legacy roots are outside the layers").

## Global constraints

- Elements: `app`, `widgets`, `features`, `entities`, `shared`. Imports point down only.
- Two slices of one layer never import each other. The one exception is `auth` <->
  `persistence`, with a comment naming `ui-migration` task 1.4.
- A slice is imported through `index.ts`, or `server.mjs` from server code (`.mjs`),
  only. `app` and `shared` have no slices.
- The legacy roots are not checked, as importer or as target.
- `api/` reaches a slice only through its `server.mjs` (added in review at Lead's word:
  `features/api` gained a `server.mjs`, and every route goes through it). A slice's
  integration spec may import the route it drives.
- A test file may import past a slice's entry, so a `vi.mock` can rebuild the entry from
  the modules behind it (`app/ConnectDialog/ConnectDialog.test.tsx`); production code may
  not (Lead, 2026-10-22, after the sx OpenSpec review). This replaced an
  `eslint-disable` in that test.
- Relative imports are checked as well as `@/` ones.
- HOO-2205's review-fix PR removed the four known violations in `widgets/assistant`
  (#136, merged before this PR opened), so this PR did not touch them.
- The rule reads paths from the config's own folder, so ESLint run from the repository
  root (an editor) checks the same as `yarn lint`.

## Review focus

1. A resolver failure turns every import "unknown", and unknown imports pass. Test:
   the four deliberate violations must fail, so a check that went silent fails the test.
2. A `vi.mock("../auth/server.mjs")` or `typeof import(...)` in a feature's
   integration spec is not an import edge. Expect no error (`agent.integration.spec.ts`).
3. A file imports its own slice by a deep path. Expect no error.
4. A legacy root imports a slice by a deep path. Expect no error.
5. `api/*.mjs` imports a slice's `server.mjs` or `shared`. Expect no error; a deeper
   path fails.

### Task 1: The rule and its test

**Files:**

- Create: `client-v2/eslint-layers.js`
- Create: `client-v2/scripts/eslint-layers.test.mjs` (run by `yarn test-api`; it
  lints with the real config, which is how `CLAUDE.md` allows build configuration
  to be tested)
- Modify: `client-v2/package.json`: `eslintConfig.extends` gains `./eslint-layers.js`;
  devDependencies `eslint-plugin-boundaries@7.2.0` and
  `eslint-import-resolver-typescript@^3.10.1`; `yarn.lock`

- [x] **Step 1: Write the test.** It uses `new ESLint({ cwd })` with the repository
      config and `lintText(code, { filePath })` on virtual files placed in real slices.
      Each case expects `boundaries/dependencies` errors, or none. The cases below came
      first; review added the rest (upward imports, entity to entity, re-export, type
      import, dynamic import, `server.mjs` from browser code, persistence to auth, and
      a run from the repository root):
  - `src/widgets/assistant/ui/Probe.tsx`: `import "../../overlays"` -> 1 error (widget -> widget, relative)
  - `src/features/agent/model/probe.ts`: `import "@/features/feedback"` -> 1 error (feature -> feature)
  - `src/shared/lib/probe.ts`: `import "@/features/feedback"` -> 1 error (shared -> features)
  - `src/widgets/home/ui/Probe.tsx`: `import "@/features/feedback/model/context"` -> 1 error whose message says "public entry"
  - `src/features/auth/model/probe.ts`: `import "../../persistence"` -> 0 (the exception)
  - `src/widgets/home/ui/Probe.tsx`: `import "@/features/feedback"` and `import "@/shared/lib/ids"` -> 0
  - `src/widgets/home/ui/Probe.tsx`: `import "../model/telemetry"` -> 0 (own slice)
  - `src/components/Probe.tsx`: `import "@/features/feedback/model/context"` -> 0 (legacy root)
- [x] **Step 2: Run the test with the rule set to `"off"`.** Run:
      `node --test scripts/eslint-layers.test.mjs`. Expected: the four violation cases fail.
- [x] **Step 3: Set the rule back to `"error"`.** Expected: the test passes. Also point the
      exception at a slice that does not exist: the two exception cases must fail.
- [x] **Step 4: Run `yarn lint`.** Expected: exactly the four `widgets/assistant` ->
      `widgets/overlays` errors on new-face `fcf0890e7`, and none on `12b6fa32d`,
      which carries HOO-2205's fix (#136).

### Task 2: The build runs it

**Files:** `client-v2/package.json` (scripts)

- [x] **Step 1: Add `lint:layers`.** It runs `eslint --quiet` with the whole
      `eslintConfig` over the five layer directories. ESLint alone with
      `eslint-layers.js` was tried first and dropped: `eslint-disable` comments that
      name rules it does not load (`react-hooks/exhaustive-deps`) become errors.
- [x] **Step 2: Put `yarn lint:layers &&` at the front of `build:bundle` and `build-fast`.**
- [x] **Step 3: Run `yarn build-fast` with a deliberate violation.** Expected: it stops
      before webpack and names the rule. Revert the violation and run `yarn build:bundle`.
      Expected: green.
