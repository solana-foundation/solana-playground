# 5.6 Menus, dialogs, tooltips and toasts: implementation plan

> **Superseded, kept as the record of how 5.6 was built.** It was executed in
> full (HOO-2061, PR #68); its checkboxes were not ticked as it ran, and its
> code blocks show the first cut, not what shipped. Review changed the
> dialogs, toasts and menus after it. What is true now is the code and
> `design.md`, section "Menus, dialogs, tooltips and toasts (5.6)".

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans
> (inline, the default) or superpowers:subagent-driven-development to
> implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Menus, dialogs, tooltips and toasts in client-v2 come from the
design system; react-toastify and the legacy `Menu`, `Modal`,
`ModalBackdrop`, `Popover`, `Toast` and `Tooltip` components are gone.

**Architecture:** `PgView` keeps its imperative API (`setModal`,
`closeModal`, `onDidOpenModal`, `setToast`, `closeToast`); only the
renderers change. A new widget, `widgets/overlays`, renders the dialog stack
in the stock `Modal` and the toasts in Sonner, and gives the 21 dialog bodies
a `ModalFrame` with the old `<Modal>` props. The four menus and the tooltip
call sites use the stock parts directly.

**Tech stack:** React 19, Radix through `radix-ui`, shadcn parts from the
in-repository registry (`yarn ds-add`), Sonner 2, vitest + Testing Library,
Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, section "Menus, dialogs,
tooltips and toasts (5.6)", and
`openspec/changes/ui-migration/specs/client-v2-overlays/spec.md`. Ticket
HOO-2061.

## Global constraints

- Every command runs from `client-v2/` with Node 22.20 first on `PATH`
  (`export PATH=~/.nvm/versions/node/v22.20.0/bin:$PATH`; `~/.local/bin/node`
  is Node 24 and yarn refuses it).
- `shared/ui` is installed with `yarn ds-add`, never edited by hand. A change
  to an installed part is made in `design-system/` and reinstalled.
- Ids, `aria-label`s and test ids survive every move.
- No empty `catch`; failures log through `createLogger("<slice>:<module>")`,
  with `report: true` when the team must hear of it.
- No nested ternaries. Imports go through a slice's `index.ts`.
- Test files build fixtures without spreads (`client-v2/AGENTS.md`).
- Telemetry prefix `overlay`, registered in
  `src/shared/lib/telemetry/prefixes.ts`; every event has a doc comment.
- `name` in telemetry is a fixed kebab-case string, never user content.
- Commits: Conventional Commits with scope `(client-v2)`, no AI attribution.
- Gate: `yarn run check` and `yarn test-e2e` green.

## Review focus

1. A dialog whose submit throws a non-`Error` (a string, `undefined`): the
   frame still shows a message and stays open. Test in Task 4.
2. Escape in a dialog while a menu or a tooltip is open inside it closes the
   inner layer first, not the dialog. Radix's layer stack does this. Check it
   by hand in Task 7.
3. A stacked dialog (a dialog opening another, as `ImportFs` does): closing
   the top one returns to the one under it with its state. Test in Task 4.
4. A right-click on the explorer's root folder opens neither our menu nor the
   browser's. `handleMenu` throws for it today. Test in Task 2.
5. A toast dispatched without `options.name` (the layout e2e dispatches a raw
   event): it still shows, and a warning is logged. Test in Task 5.

  if (typeof error === "string" && error) return error;
  return "Unknown error";
};

export const ModalFrame = ({ name, title, buttonProps, size = "default", children }: ModalFrameProps) => {
  const [error, setError] = useState("");
  const [busy, setBusy] = useState(false);

  useEffect(() => {
    overlayTelemetry.track("overlay_modal_opened", { name });
  }, [name]);

  const submit = async () => {
    if (!buttonProps || buttonProps.disabled || busy) return;
    setBusy(true);
    try {
      const data = await buttonProps.onSubmit?.();
      if (!buttonProps.noCloseOnSubmit) PgView.closeModal(data);
    } catch (e) {
      setError(messageOf(e));
      overlayTelemetry.track("overlay_modal_submit_failed", { name });
      // Shown to the user in the dialog; logged so a pattern of failures is visible
      log.warn("dialog submit failed", { context: { name }, error: e });
    } finally {
      setBusy(false);
    }
  };
  // render BaseModalFrame with title = title === true || !title ? PROJECT_NAME : title,
  // hideTitle = !title, onCancel = buttonProps?.onSubmit ? () => PgView.closeModal() : undefined
};
