# The assistant thread on the design system (5.18) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Executed** on 2026-10-19 (HOO-1794). Where the code went another way, the step below says so.

**Goal:** The assistant's thread (messages, tool lines, the working indicator,
diffs and approval cards, the empty state) drawn from the design system at
every width, with the stored transcript and approval behaviour unchanged.

**Architecture:** A `Base` + connected pair in `widgets/assistant`:
`BaseThread` (MessageScroller, empty state, items, working marker),
`BaseThreadItem` and `BaseApprovalCard` take props only; `Thread` reads
`PgAssistant`, the lesson and `turn.send`, and replaces
`views/sidebar/assistant/Component/Chat.tsx` and `ChatItem.tsx`, which are
deleted.

**Tech Stack:** React 19, Tailwind 4, design-system registry (`yarn ds-add`),
`@shadcn/react` message-scroller primitive, vitest + Testing Library,
Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "The assistant thread
(5.18)"; `openspec/changes/ui-migration/specs/client-v2-assistant/spec.md`.

## Global Constraints

- Node `~/.nvm/versions/node/v22.20.0/bin` on PATH; commands run from `client-v2/`.
- `shared/ui` is installed with `yarn ds-add`, never hand-edited; a needed change to a part is made in `design-system/` and reinstalled.
- Kept verbatim: log "Conversation"; status "Assistant is working"; buttons "Make this change", "Write it for me", "Skip this step", "Apply", "Reject", "Allow", "Deny"; outcome "not applied -- the session ended before you answered".
- Status words: `Proposed`, `Applied`, `Declined`, `Not answered` (replace today's upper-case `PROPOSED` etc.; CSS may upper-case them).
- `ChatItem`, `ApprovalRequest`, `resolveApproval` and the codec do not change.
- No empty `catch`. The thread logs nothing of its own: a send failure is `useTurn`'s (`reportButtonFailure`), and so is a failed "Skip this step".
- No nested ternaries (`STATUS_LABEL` / `OUTCOME` as `Record` lookups).
- Tests build fixtures with explicit fields, never a spread (`client-v2/AGENTS.md`).
- Telemetry, prefix `assistant`: `assistant_approval_answered {kind: "patch" | "command", answer: "allow" | "deny"}`, `assistant_suggestion_picked`, `assistant_make_change_requested`.
- Below `md`: approval actions one row of 44 px targets (`h-11`); diff content `max-h-[min(15rem,40dvh)] overflow-auto`.

## Review Focus

1. A pending card answered twice (double tap) — one `resolveApproval` effect and one `assistant_approval_answered`. Test in Task 6.
2. A reply with a 200-character code line at 390 px — no horizontal page scroll. e2e in Task 7.
3. A patch whose `before` is `null` (new file) — all lines `added`, stat `+n −0`. Test in Task 3.
4. A thread restored with a pending card — "Not answered", no Apply. e2e in Task 7, unit in Task 3.
5. An assistant item with empty `text` mid-stream — renders nothing, the working marker shows. Test in Task 5.
