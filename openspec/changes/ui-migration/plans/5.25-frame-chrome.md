# Frame chrome (5.25) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the four-column frame the prototype's chrome: flush columns with 1 px dividers, a 44 px bar over the assistant and the stage, a full-width stage-tab row, and hidden columns that take no width.

**Architecture:** The shell (`widgets/layout-shell`) owns the chrome. `BaseLayoutShell` loses its inset and gutters and gains a `stageBar` slot drawn by a new `BaseStageBar`; `LayoutShell` connects it to the layout state it already holds. Flow's old `stageBar` (the `Stepper`) becomes `stageTabs`. The assistant's bar is 5.17's `BaseAssistantHead`, only resized.

**Tech Stack:** React 19, Tailwind 4 + `shared/ui` (DS), styled-components (legacy panels), react-resizable-panels, vitest + RTL, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md` "Frame chrome (5.25)"; `specs/client-v2-layout/spec.md` ("The frame is flush, with a bar over each column", "Folding the project panel", "A layout saved before the column bars", "Widening the assistant").

**Base:** stacked on HOO-2067's branch (5.17) until it merges into `new-face`; then rebase onto `new-face`. Never edit `widgets/assistant/*` beyond Task 4's class change.

## Global Constraints

- Bars: 44 px (`h-11`), 1 px bottom line in `border`. Stage tabs row: 38 px. Handles: the stock `ResizableHandle` (1 px, `bg-border`), no `w-2`.
- Ids, aria-labels and test ids kept: "Collapse assistant" (5.17's head), "Expand assistant", "Collapse project panel", "Expand project panel", "New file", `flow-stage-tab-*`, `#tabs`, `#root-dir`, `flow-left-tab-*`.
- New labels: "Hide the assistant" (stage bar, assistant open), "Documentation" (link, `https://solana.com/docs`, new tab, `rel="noreferrer"`).
- `LAYOUT_VERSION` stays 2; no new storage key.
- No nested ternaries; no empty catch; failures through `createLogger(..., {report: true})`.
- Phone (< 720) unchanged: the pager still gets the `Stepper` as its bar.
- Keys unchanged: ⌘B, ⌘E, Ctrl+R, Ctrl+J, Ctrl+1..4.

## Review Focus

1. 720–767 px: the files column sits in the nav Sheet and "Expand project panel" is already the left-edge opener → the stage bar must not render a second button of that name (Task 2 test).
2. 768–1023 px: the assistant is a Sheet. Amended in Task 6 (the right-edge opener sat on the bar's help link): the stage bar's toggle opens the Sheet and the edge opener is removed, so "Expand assistant" stays one button (LayoutShell test "opens the assistant Sheet from the bar between 768 and 1023 px").
3. A hidden files column must still reopen by ⌘E and the stage bar. Amended in review: it leaves the work group with its handle (a 0 px panel snapped open, and its handle doubled the assistant's drag), so it no longer reopens by drag; `pendingCreate` was removed with the rail's "New file", its only producer.
4. Widen then hide then show: the assistant reopens at its pre-widen width (5.17's `wideFrom` logic) and `layout_assistant_widened` fires only on clicks, not on the auto-narrow when hiding (Task 5 test).
5. A v2 layout saved with the old frame (files folded, assistant 30%) restores with files hidden and assistant at its width (Task 6 e2e).
