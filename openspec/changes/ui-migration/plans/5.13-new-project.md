# 5.13 New project Implementation Plan

> **Executed 2026-10-20.** The review fixes changed some interfaces below:
> `StartFromScratch({onStarted?})` (New project closes its dialog, Home
> nothing); `BaseStartFromScratch` takes one `start: Start` union
> (`idle | creating | invalid | failed`). Rebased onto 5.9's rewrite (PR
> #116): the cards' Open is 5.9's `useCardOpen` (now with options), the
> list hooks are `useTutorialList` / `useProgramList` returning a
> `CardList` (`model/lists.ts`), and New project's state is
> `useNewProject`, held by `NewWorkspaceModal` above its frame. The code is
> the reference.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New project looks like the prototype's "What do you want to build?":
Start from scratch on top, Tutorials / Programs as a boxed Segmented with
counts and a search beside it, the catalog's ActionCards below; a page of its
own on a phone, rows ending in a chevron.

**Architecture:** Stacked on HOO-2064 (Slava, 2026-10-20), which brings
`widgets/catalog` and `shared/ui/action-card`. The card grid and the two card
sources move out of the catalog pages into parts the pages and New project
share. New project's content lives in `widgets/catalog`; Start from scratch
becomes `features/new-project`, used by New project and by Home. The dialog
shell stays `views/flow/gallery/NewWorkspaceModal.tsx`, a thin legacy wrapper
around `ModalFrame` (a widget may not import `widgets/overlays`; legacy roots
may), so `PgView.setModal(NewWorkspaceModal)` and with it
`PgView.onDidOpenModal`, which closes the left Sheet, stay as they are.

**Tech Stack:** React 19, Tailwind 4, design-system parts in `shared/ui`
(Modal via `ModalFrame`, Segmented, ActionCard, InputGroup, Input,
FieldError, BrandButton, Tag), vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md` (section "New project
(5.13)", added in Task 1), `specs/client-v2-layout/spec.md`; ticket HOO-2068;
prototype https://solana-playground-ds.vercel.app/#app → New project.

## Global Constraints

- Kept: the dialog's accessible name "What do you want to build?",
  `data-gallery-modal`, the field label "Project name", the button "Start →"
  (e2e match `/^Start/`), Home's `Project name`/`Start` inside its region.
- No hand edits in `shared/ui`; nothing new to install (action-card,
  input-group come with HOO-2064).
- No empty `catch`; failures log through `createLogger(...)` with
  `report: true`.
- Telemetry (agreed with Slava 2026-10-20, names fitted to the prefix rule):
  `features/new-project`, prefix `new_project`: `new_project_started
  {framework}`, `new_project_start_failed {framework}`; `widgets/catalog`:
  `catalog_tab_switched {tab}` (New project's Segmented). Card opens keep
  `catalog_item_opened` / `catalog_open_failed`.
- No nested ternaries; state as unions; no spreads that build test fixtures.

## Review Focus

1. Programs list fails to load while Programs is the chosen tab: the count
   reads `?`, the grid shows "Could not load the programs." with Retry, and
   Start from scratch still works.
2. A second press on Start while a project is being made does nothing (one
   workspace, not two).
3. A duplicate or invalid name: the message shows under the field and Start
   stays usable after the name is edited.
4. Opening a tutorial or program from the dialog closes the dialog only on
   success; a failure stays on its card.
5. 390 px: the dialog is a full page, each card is one target ending in a
   chevron, no horizontal scroll.
