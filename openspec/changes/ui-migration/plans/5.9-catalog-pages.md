# Tutorials and Programs pages (5.9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tutorials and Programs in the navigation (and Home's tiles, and
the `/tutorials` and `/programs` links) open pages with a search field and
cards in place of the assistant and the work; opening a card opens the
tutorial or imports the program, and a project open before comes back as it
was.

**Architecture:** A new widget `widgets/catalog` holds the open page
(`catalogPage`, a tiny store: `"tutorials" | "programs" | null`), its
closing rules (`useCatalogPage`), its telemetry, and the views
(`BaseCatalogPage`, `TutorialsPage`, `ProgramsPage`). `LayoutShell` gains an
optional `page` slot `{ title, content }`: under Home it stands in Home's
place; over an open project it covers the columns with the work still
mounted and `inert` under it; on a phone it is the work page. `Flow` wires
the store into the shell, `AppNav`, `ProjectList` and Home. The legacy
routes go to `/` and open their page; upstream's list views, the sidebar
`Component`s and `FilterGroups` are deleted.

**Tech Stack:** React 19, TypeScript, Tailwind 4 with the design system in
`shared/ui` (`yarn ds-add`), vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "Tutorials and Programs
pages (5.9)"; `specs/client-v2-layout/spec.md`, requirements "The navigation
opens the gallery and the pages", "Tutorials and Programs are pages", "The
pages are measured", "A start with no project opens on Home".

## Global Constraints

- Branch stacks on #92 (HOO-2063); rebase on it whenever it moves. PR into
  `new-face` once #92 merges.
- Every command runs from `client-v2/` with Node 22.20
  (`PATH=$HOME/.nvm/versions/node/v22.20.0/bin:$PATH`).
- `shared/ui` is installed, never hand-edited: `yarn ds-add input-group`
  after adding its registry entry in `../design-system/registry.json`.
- Ids that exist today survive: the nav items' names ("Home", "New
  project", "Tutorials", "Programs"), `[data-gallery-modal]`,
  `#gallery-tab-*`, `phone-pager`, "Menu", `flow-stage-*`.
- No empty `catch`; failures log through `createLogger("catalog:<module>")`
  with `report: true` and tell the user. No nested ternaries.
- Telemetry prefix `catalog` (slice `catalog`); events exactly:
  `catalog_shown {page, via: "nav" | "home" | "link"}`,
  `catalog_searched {page, empty: boolean}` (500 ms rest, non-empty query),
  `catalog_item_opened {page}`, `catalog_open_failed {page}`.
- A widget never imports another widget: `Flow` (legacy root) passes
  callbacks between `catalog`, `app-nav` and `home`.
- Tests build fixtures without spreads (`client-v2/AGENTS.md`).

## Review Focus

1. A page opened over a project, then closed: the editor shows the same file
   and the console keeps its output (the work never unmounted). Task 5 pins
   that the work stays in the DOM; e2e "Back to the open project" pins the
   file.
2. A cancelled program import (`ImportCancelledError`) is neither a failure
   event nor an error on the card. Task 4.
3. Typing fast sends one `catalog_searched`, not one per key; clearing the
   field sends none. Task 3.
4. `/programs` on a fresh load with no project lands on Home with the
   Programs page over it, not on an empty work. Task 7 (`decideStart`).
5. The shell's keys (Ctrl+R, Ctrl+J, ⌘E) do nothing while a page covers
   the work, so nothing invisible changes the saved layout. Task 5.

**Interfaces — Produces:**
```ts
interface CatalogCard {
  id: string;            // tutorial name, or program repo
  title: string;
  description: string;
  eyebrow: string;       // "Beginner · Anchor"
  media: string;         // thumbnail or icon URL
  tags?: string[];       // shown as Tag

  error?: string;        // the card's own failure

  label: string;               // "tutorials" | "programs" → "Search tutorials"
  query: string;

}
```

`Open <title>`); `Empty` "No <label> match “<query>”." when filtered to
nothing; "Loading <label>…" while `cards === null`; the failure with a
"Retry" `Button`. Filtering is the connected side's job.
