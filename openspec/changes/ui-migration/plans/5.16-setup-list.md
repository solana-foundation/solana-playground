# The Get set up checklist (5.16) Implementation Plan

> **Superseded in part by HOO-2330:** the network step is always done, so
> `networkChosen`, `markNetworkChosen`, `onChooseNetwork` and `openSettings`
> are gone, and the store keeps the user's fold instead (`design.md`, 5.16).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "Get set up · n of 4" in the navigation, four steps that run their
action, gone for good on the device once dismissed or finished.

**Architecture:** A widget `widgets/setup-list`: a device store (one
`localStorage` key, read like `app-nav/model/pins.ts`), `BaseSetupList` drawn
from the design system's `setup-list`, and `SetupList` reading the four
states. Actions that belong to other widgets (Connect a model, the settings)
come in as props from `views/flow/Flow.tsx`, so no widget imports another.

**Tech Stack:** React 19, Tailwind 4, the design system's `setup-list`
(Radix Collapsible), vitest + Testing Library, Playwright.

**As built (2026-10-19):** executed inline; where the code differs from a
step below (the one-way `mark(which)`, steps built from `SETUP_STEPS`,
`onChoose` once per pick, the network step as a settings trigger, the e2e
connecting a key-based model), the design and the spec describe the code.

**Spec:** `openspec/changes/ui-migration/design.md`, "The Get set up checklist
(5.16)"; `specs/client-v2-layout/spec.md`, "The Get set up checklist".

## Global Constraints

- Branch off `new-face`, PR into `new-face` (HOO-2075).
- Copy, verbatim: "Get set up", "Connect the assistant", "Choose a network",
  "Sign in with GitHub", "Connect a wallet"; the design system's dismiss is
  named "Dismiss the checklist".
- `shared/ui` is installed with `yarn ds-add setup-list`, never hand-edited.
- Telemetry prefix `setup` (slice `setup-list`); events `setup_item_picked
  {item}`, `setup_dismissed {done}`, `setup_completed`; `item` is
  `assistant | network | github | wallet`.
- Logger namespace `setup-list:<module>`; no empty `catch`; an action that
  throws: `log.error(e, {report: true})` + toast.
- Storage key `setup-list`, value `{dismissed: boolean, completed: boolean,
  networkChosen: boolean}`.
- Tests build fixtures without spreads (`client-v2/AGENTS.md`).
- Gate: `yarn run check` and `PORT=<slot> yarn test-e2e
  e2e/setup-list.e2e.spec.ts` only (the spec this PR adds).

## Review Focus

- Storage blocked or holding junk: the checklist shows with nothing done
  stored, and logs once; it never takes the navigation down (Task 1).
- Dismiss while storage refuses the write: the list still hides for this
  page, the failure is logged (Task 1, `dismiss` test).
- Settings already open when "Choose a network" is clicked: they stay open
  on the network, not toggled shut (Task 4, `openSettings`).
- All four done on load (returning user, fresh device): `setup_completed`
  sent once and the list never flashes (Task 3).
- The user closes the wallet setup or cancels the sign-in from the step: logged
  at info, no toast (Task 3).

### Task 3: `SetupList`, connected

**Files:**
- Create: `src/widgets/setup-list/ui/SetupList.tsx`, `SetupList.test.tsx`
- Modify: `src/widgets/setup-list/index.ts`

**Interfaces:**
- Consumes: Task 1 store and telemetry, Task 2 `BaseSetupList`.
- Produces: `SetupList({ onConnectAssistant(): void; onChooseNetwork(): void })`.
  States: `PgAssistant.isConnected` (re-render on `PgAssistant.onDidChange`,
  imported from `@/views/sidebar/assistant/store`), `marks.networkChosen`
  with value `PgConnection.onDidChangeCluster`'s name, `PgSession.get()`
  (value `login`), `useWallet()` (value
  `PgCommon.withMaxLength`-style short address as the account row shows it:
  reuse whatever `BaseSessionFooter` uses, through `@/utils`).
  Renders `null` while `marks.dismissed || marks.completed`.
  Actions: `github` -> `PgSession.signIn()`, a `SignInFailed`
  (`isSignInFailure`) logged at info, anything else `report: true`;
  `wallet` -> `PgCommand.connect.execute()`, `isSetupRejected` at info, else
  `report: true` + toast "Couldn't connect the wallet."; the other two call
  their props. Every click sends `setup_item_picked {item}`; dismiss sends
  `setup_dismissed {done}` then `mark({dismissed: true})`.
  An effect: when all four are done and `completed` is false,
  `mark({completed: true})` and `setup_completed` once.
