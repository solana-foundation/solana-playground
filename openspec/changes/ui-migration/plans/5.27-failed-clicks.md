# Failed clicks tell the user (5.27) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A clicked action that fails shows a toast saying what did not happen, once; a failure the terminal already printed shows nothing more (HOO-2100).

**Architecture:** `reportButtonFailure` becomes a factory taking the call site's action phrase and returning the `onError` handler. The handler logs as today and, unless the failure was marked as shown, raises one replaceable toast through `PgView.setToast`. `PgTerminal.process` marks every failure its terminal printed. Every call site gets its phrase.

**Tech Stack:** React 19, vitest + Testing Library, Playwright, Sonner behind `PgView.setToast` (5.6).

**Spec:** `openspec/changes/ui-migration/design.md`, "Failed clicks (5.27)"; `specs/client-v2-buttons/spec.md`, "A failing click tells the user once".

## Global Constraints

- Toast text: `Could not <action>.` The raw error never reaches the screen.
- Toast options: `{ name: "button-failed", id: "button-failed" }` (one id, so a repeat replaces).
- Logging unchanged: `createLogger("ui:button")`, `log.error(error)`, never `report: true`.
- A marked failure (shown by the terminal or by its own UI) is logged, never toasted.
- Object failures are matched by identity (`WeakSet`); a thrown primitive by value (`Set`, capped at 20 entries, oldest dropped).
- No empty `catch`; ids, `aria-label`s and test ids unchanged; `shared/ui` not edited.
- Gate: `yarn run check`, then `PORT=<slot port> yarn test-e2e e2e/client-v2-buttons.e2e.spec.ts` (the only e2e spec this change touches).

## Review Focus

- A thrown string from `Send` (`throw txResult.err`) after the terminal printed it: no toast. Test in Task 2.
- Two failures in a row: one toast on screen, the second's text. Pinned by the fixed `id` (Task 1 asserts the options).
- An action that catches and shows its own error inline (`TutorialsTab`, `ProgramsTab`) and never rethrows: no toast, because `onError` never fires. No new code; Task 3's audit confirms.
- `ExportWorkspace`'s own "Could not export …" toast: it returns `false` instead of rethrowing, so no second toast. Task 3's audit confirms.
- A failure thrown before `PgTerminal.process` prints (the terminal not mounted): not marked, so toasted. That is correct: nothing was shown.
