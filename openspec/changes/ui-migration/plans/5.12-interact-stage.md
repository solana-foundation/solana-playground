# The Interact stage (5.12) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Interact stage is drawn with the design system: a Tailwind toolbar, one `StageEmpty` for every state in which the program cannot be called yet, and the instruction form restyled as cards with `Tag` labels and `code-block` results, with no behaviour change.

**Architecture:** A pure `interactSurface()` in `views/flow/stages/interact-surface.ts` picks one of eight surfaces from the project and program info, in the order the embedded `Test` component checks today. `BaseInteract.tsx` draws the toolbar and the surface from props; `Interact.tsx` stays the connected wrapper and passes the form (`Test`) and the IDL action (`IdlActions`) as slots. `Test` loses its guard returns and takes `idl` as a prop; its subtree under `views/sidebar/test/Component` drops every styled-component.

**Tech Stack:** React 19, Tailwind 4, shadcn on Radix (design-system registry), vitest + Testing Library, Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "The Interact stage (5.12)"; `specs/client-v2-stages/spec.md` (requirement "The Interact stage says what is missing", scenarios "Interact before a deploy" and "The Interact action at the foot on a phone"); HOO-1676.

## Global Constraints

- `shared/ui` is installed, never edited by hand: `yarn ds-add code-block`. Layout around a DS part is a `className` on it.
- Ids, `aria-label`s and test ids do not change: `flow-stage-panel-interact`, `flow-stage-tab-interact`, the input ids `instruction.name + prefix + name` that `InstructionInput`'s `updateRefs` looks up by `document.getElementById`. Texts kept: "Interact", "Deployment", "none yet", "Load IDL file", "Test", "Fill", "Reset", "Fetch", "Fetch All", "Result", "Args", "Accounts", "Instructions", "Events".
- Exact copy for the surfaces (design.md table):
  - `no-project`: "No project open" / "Open a project or start a new one to call its program."
  - `not-built`: "Nothing to call yet" / "Build the program first. Once it is deployed, its instructions show up here, ready to call." / BrandButton "Go to Build"
  - `no-idl`: "No IDL yet" / "This program's Anchor IDL was not found. Load the IDL file to call its instructions." / the `idlLoad` slot
  - `no-program-id`: "No program id" / "The program has no public key."
  - `bad-idl`: "This IDL can't be read" / error notice "You've imported a corrupted IDL. Please double check you've imported an Anchor IDL."
  - `unreachable`: "Can't reach the network" / error notice "Connection error. Please try changing the RPC endpoint from the settings."
  - `not-deployed`: "Nothing to call yet" / "Deploy the program first. Once it is on {cluster}, its instructions show up here, ready to call." ({cluster} is "the network" while unknown) / BrandButton "Go to Deploy"
- At most one `BrandButton` per screen; Test, Fill, Reset, Fetch, Fetch All are not brand.
- Every `AsyncButton` and `CopyButton` passes `onError={reportButtonFailure}`.
- No empty `catch`; no nested ternaries (an `if` chain or a `Record`).
- Tests: no spread to build a new fixture shape (client-v2/AGENTS.md).
- Node 22.20 (`export PATH=~/.nvm/versions/node/v22.20.0/bin:$PATH`); every command runs from `client-v2/`.
- Commits: Conventional Commits, `(client-v2)` scope; no AI attribution.
- Not edited: `components/SearchBar/**` (five users, HOO-2064), `components/CodeBlock/**` (Markdown uses it), `widgets/layout-shell/**`, `views/flow/header/**`, `views/flow/console/**`.

## Review Focus

1. **The toolbar's "Load IDL file" and the `no-idl` stage action are the same button twice.** My call: in `no-idl` the toolbar does not render `idlLoad`, the stage's foot does; one button named "Load IDL file" is on screen in every surface. Pinned by a `BaseInteract` test (Task 2).
2. **Instruction refs by DOM id.** `updateRefs` fills dependent inputs through `document.getElementById(instruction.name + key + name)`; the restyle must keep `id` on the `SearchBar`. Pinned by an `InstructionInput` id assertion (Task 3).
3. **`onChain` undefined while the first fetch is pending** reads as `unreachable`, as today. Kept on purpose (no behaviour change); pinned by an `interactSurface` case (Task 1) so a later change is deliberate.
4. **Picking a deployment still targets it**, and leaving the stage hands control back (`targetedRef`). `Interact.tsx`'s effect is moved untouched; Task 2 passes `onPick` through, and its test checks the callback gets the id.
5. **Long values in a narrow column** (a 44-char program id, nested JSON) must scroll inside their card, not widen the stage at 390 px. `code-block` content gets `overflow-x-auto`; the e2e phone scenario asserts no horizontal page scroll (Task 4).

**Interfaces:**
- Produces:

  ```ts
    | "no-project" | "not-built" | "no-idl" | "no-program-id"
    | "bad-idl" | "unreachable" | "not-deployed" | "ready";
  export interface InteractFacts {
    /** A workspace is open, or the explorer is temporary */
    hasProject: boolean;
    /** `PgProgramInfo.idl`; only `instructions` is read */

    hasProgramId: boolean;
    /** `PgProgramInfo.onChain`; undefined when the read failed */
    onChain: { deployed: boolean } | undefined;
  }
  export const interactSurface: (f: InteractFacts) => InteractSurface;
  ```
