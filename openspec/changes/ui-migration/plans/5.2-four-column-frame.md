# Four-column frame Implementation Plan

> **Executed.** Task 5.2 shipped from this plan, and its steps are ticked.
> The code and `design.md` ("The four-column frame (5.2)") are authoritative
> where they differ. The signatures below were brought up to date after the

> `LayoutShell.tsx`, `BaseAppNav.tsx` and `AppNav.tsx` remain authoritative. The review

**Goal:** The app opens in the prototype's frame (navigation, assistant on
the left, a stage bar over Files and the stage, the console under the
stage) with no header, every piece inside moved unchanged.

**Architecture:** `widgets/layout-shell` keeps owning the frame: the stock
`Sidebar` now holds the navigation, the horizontal group puts the assistant
before a new `work` panel, and `work` holds the stage bar over a second
horizontal group (`files` | the existing vertical stage/console group). A new
widget, `widgets/app-nav`, draws the navigation from installed `Sidebar*`
parts. `Flow` stops rendering `Header`; its pieces go into the shell's
slots.

**Tech Stack:** React 19, `react-resizable-panels` v4 through
`shared/ui/resizable`, the stock shadcn `Sidebar`, `lucide-react`,
styled-components for the legacy pieces, vitest + Testing Library,
Playwright.

**Spec:** `openspec/changes/ui-migration/design.md`, "The four-column frame
(5.2)" and "The layout shell (5.1)"; `specs/client-v2-layout/spec.md`.

## Global Constraints

- Ids, `aria-label`s and test ids survive: `flow-console-drawer-body`,
  `flow-left-tab-*`, `flow-stage-*`, `#tabs`, `#root-dir`, "Collapse/Expand
  project panel", "Collapse/Expand assistant", "Console", "New file",
  "Expand project panel" at the left edge below 768 px.
- `shared/ui` is never edited by hand.
- No empty `catch`; failures go through `createLogger(...)` with
  `report: true`.
- Open a panel with `resize(openSize)`, never `expand()`; save sizes only from
  `onLayoutChanged` with `isUserInteraction`; folded panels keep no sizes.
- One `localStorage` key, `layout`, under 200 bytes.
- Keys: ⌘B navigation, ⌘E files, Ctrl+R assistant, Ctrl+J console, Ctrl+1..4
  stages.
- Breakpoints unchanged: `LAYOUT_BREAKPOINTS = {compact: 1024, left: 768,
  phone: 600}`.
- Telemetry: `layout_panel_toggled.panel` is `nav | files | assistant |
  console`; `nav_item_opened {item: home | new-project | tutorials |
  programs}`, prefix `nav`.
- No restyling of any panel's contents. Test files build fixtures without
  spreads (`client-v2/AGENTS.md`).

## Review Focus

- A `v: 1` layout with the project panel folded: the files column must load
  folded, the console as saved, the navigation open (Task 1 test).
- A `v: 1` layout with an `h` map: `h` is dropped, not misread as the new
  group, and nothing is reported as corrupt (Task 1 test).
- ⌘E pressed while Monaco has focus: on macOS Monaco's own binding takes
  it; the e2e presses it with focus outside the editor, and the button still
  works (Task 7).
- The footer's menus (profile, cluster) open downward from a chip at the
  bottom of the window and would be cut off: they must open upward there
  (Task 6 check, e2e "Everything the header did").
- Crossing 768 px moves `LeftPanel` between the work group and the Sheet:
  `pendingCreate` already lives in `Flow`, so the rail's "+" survives (e2e
  "the rail's + expands the panel" keeps passing on ⌘E).
